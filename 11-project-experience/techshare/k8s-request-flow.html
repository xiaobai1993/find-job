客户端发起 HTTPS 请求。域名格式通常为 api.meican.com，请求头携带 JWT Token 或内部 service token。
GET /v2/orders HTTP/1.1

HTTPS/2 JWT TLS 1.3
客户端延迟
~0ms
Route53 将域名解析为 NLB 的 DNS 名称。支持加权路由 (Weighted Routing) 实现多集群流量分配，TTL 通常设为 60s。
; Route53 Record
api.meican.com.  60  A  ALIAS
  → eks-fan2-nlb-xxx.elb.amazonaws.com.cn

; 支持加权路由
eks-fan2  Weight=80
eks-fan3  Weight=20
Route53 Weighted Routing TTL 60s
DNS 解析
~1-5ms
Network Load Balancer 工作在 L4，保留客户端源 IP（Proxy Protocol v2），跨 3 个可用区（cn-northwest-1a/b/c）进行四层转发，将流量分发到 Kong Pod。
# NLB 配置要点
- 协议: TCP 443
- 跨 AZ 负载均衡: enabled
- 保留源IP: Proxy Protocol v2
- 健康检查: TCP:8000/10s
- 目标组: Kong Pod NodePort
L4 TCP 3 AZ Source IP 保留
NLB 转发
<1ms
Kong Gateway 接收请求后依次执行 Plugin Chain。通过 KongPlugin CRD 配置，插件按优先级顺序运行：限流 → 鉴权 → 熔断 → 路由。
# KongIngress 路由规则
apiVersion: configuration.konghq.com/v1
kind: KongIngress
metadata:
  name: order-service-ingress
route:
  methods: [GET, POST]
  strip_path: true
  preserve_host: false
---
# KongPlugin: Rate Limiter
apiVersion: configuration.konghq.com/v1
kind: KongPlugin
metadata:
  name: rate-limit-100
plugin: rate-limiting
config:
  minute: 100
  policy: redis
KongPlugin CRD Plugin Chain Lua/Nginx
Kong 处理
~2-5ms
Kong 通过 set-upstream 插件将请求转发到目标 Service 的 ClusterIP。kube-proxy 在每个 Node 上维护 iptables 规则，将 ClusterIP 转换为 PodIP。
# Service 定义
apiVersion: v1
kind: Service
metadata:
  name: order-service
  namespace: meican
spec:
  type: ClusterIP
  selector:
    app: order-service
  ports:
  - port: 80
    targetPort: 8080

# DNS: order-service.meican.svc.cluster.local
ClusterIP kube-proxy CoreDNS
Service 路由
<0.5ms
iptables 在 PREROUTING 链通过 DNAT 规则将 ClusterIP 随机替换为一个后端 Pod IP。Istio 接管后，iptables 还会劫持所有出站流量到 Envoy（port 15001）。
# kube-proxy 生成的 iptables 规则
-A KUBE-SERVICES -d 10.96.1.100/32 \
  -p tcp --dport 80 \
  -j KUBE-SVC-ORDER

-A KUBE-SVC-ORDER -m statistic \
  --mode random --probability 0.333 \
  -j KUBE-SEP-POD1
-A KUBE-SVC-ORDER \
  -j KUBE-SEP-POD2   # 余下均匀分配

-A KUBE-SEP-POD1 -j DNAT \
  --to-destination 172.16.1.5:8080
DNAT 负载均衡 iptables PREROUTING
DNAT 转换
<0.1ms
Istio 注入的 Envoy Sidecar 通过 iptables 劫持入站流量（port 15006，UID 1337 绕过）。执行 mTLS 终止、链路追踪 Header 注入（Jaeger B3/W3C Trace），应用 VirtualService 流量策略。
# Istio iptables 劫持规则
iptables -t nat -A PREROUTING -p tcp \
  -j ISTIO_INBOUND
iptables -t nat -A ISTIO_INBOUND \
  -p tcp --dport 8080 \
  -j ISTIO_IN_REDIRECT
iptables -t nat -A ISTIO_IN_REDIRECT \
  -p tcp -j REDIRECT --to-port 15006

# 绕过: 进程 UID=1337 (Envoy自身)
iptables -t nat -A OUTPUT \
  -m owner --uid-owner 1337 -j RETURN

# VirtualService: 金丝雀发布
spec:
  http:
  - match: [headers: {x-canary: exact: "true"}]
    route: [{destination: {subset: v2}}]
  - route: [{destination: {subset: v1, weight: 90},
             {destination: {subset: v2, weight: 10}}]
Envoy Sidecar mTLS Jaeger Tracing VirtualService
Envoy 处理
~1-2ms
业务容器处理请求。通过 IRSA（IAM Roles for Service Accounts）无密钥访问 AWS 服务。通过 Tower 平台注入环境变量，配置数据库连接等信息。Fluent-bit Sidecar 收集日志发送至 Pulsar。
# IRSA: Pod 无需 AK/SK
apiVersion: v1
kind: ServiceAccount
metadata:
  name: order-service-sa
  annotations:
    eks.amazonaws.com/role-arn:
      arn:aws:iam::123456:role/order-role
# EKS Webhook 自动注入:
# AWS_WEB_IDENTITY_TOKEN_FILE
# AWS_ROLE_ARN

# Tower 注入的环境变量
env:
  DB_HOST: rds.meican.internal
  REDIS_ADDR: redis.meican.internal:6379
  PULSAR_URL: pulsar://pulsar.meican.internal
