# 退款菜品校验逻辑分析

## 1. 触发条件

只有同时满足三个条件才会进行菜品校验：

```go
// 1. 不是全额退款 (!param.FullRefund)
// 2. 传入了取消菜品信息 (param.ProductDetailsHasCancelProductItems())
// 3. 是 Meican 产品类型 (param.ProductType.IsMeican())
if !param.FullRefund && param.ProductDetailsHasCancelProductItems() && param.ProductType.IsMeican() {
    bizErr := t.checkProducts(ctx, param, paymentSlips, refundSlips)
    ...
}
```

另外，**外卖业务的部分退款必须传菜**：

```go
if paymentSlips[0].IsGroupDeliveryBiz() && !param.ProductDetailsHasCancelProductItems() {
    return 0, bizerr.NewWithMsg(..., "product details missing product items")
}
```

---

## 2. 校验核心逻辑

### 步骤一：计算当前可退商品库存

```go
// 1. 加所有支付单中的商品数量（OrderProducts）
// 2. 减所有已退款/退款中的商品数量（CancelProducts）
// 3. 减所有改单取消的商品数量
for _, paymentProductInfo := range productInfos {
    for _, product := range paymentProductInfo.GetOrderProducts() {
        // + 下单数量
        productMap[key] += item.GetQuantity().GetQuantity()
    }
    for _, product := range paymentProductInfo.GetCancelProducts() {
        // - 已取消数量
        productMap[key] -= item.GetQuantity().GetQuantity()
    }
}
```

### 步骤二：校验本次退款数量是否合法

```go
// 检查本次要退款(CancelProducts)的数量是否超过可退数量
for _, product := range param.ProductDetails.GetCancelProducts() {
    if productMap[key] < item.GetQuantity().GetQuantity() {
        return "PartialRefund product quantity is invalid"
    }
}
```

---

## 3. 为什么要做菜品校验？

| 用途 | 说明 |
|------|------|
| **防超退** | 防止退款数量超过实际购买/可退数量 |
| **精准核算** | 外卖/团餐业务按商品维度核算成本、补贴 |
| **渠道对接** | **钱包渠道退款时需要传递商品信息**（见代码第617-627行） |
| **财务对账** | 退款商品明细用于财务对账和流水记录 |
| **改单兼容** | 支持"支付→改单（部分取消）→再退款"的复杂场景 |

## 4. 菜品信息的实际用途 - 传给钱包渠道

在 `Refund` 函数中（refund_core.go 第615-645行）：

```go
if subSlip.AccountType.IsWallet() {
    // 获取退款菜品信息
    product, bizErr := t.RefundSlipHelper.GetRefundProductInfoByRefundSlipID(...)
    if product != nil {
        // ✅ 把菜品信息传给钱包渠道进行退款
        param.Products = &commonv2pb.ProductDetails{
            OrderProducts:  product.ProductDetails.OrderProducts,
            CancelProducts: product.ProductDetails.CancelProducts,
        }
    }
}

// 调用支付渠道退款
refundResult, bizErr := t.payChannel.Refund(ctx, subSlip.AccountType, ..., param)
```

## 5. 关键注意事项

代码中有一个重要的注释（refund_core.go 第235-237行）：

```go
// NOTE 先只打印日志，不返回错误，跑一段时间，
// 等确认上游以前的接入没有问题后，再打开
```

**说明**：这个校验目前只是**告警日志级别**，不会真正阻断退款，属于灰度上线阶段。

---

## 总结

**菜品校验不是为了支付系统内部算金额**（金额校验是单独做的），而是：

1. **业务完整性**：外卖/团餐按商品维度退款是业务刚需
2. **下游依赖**：钱包等支付渠道退款时需要商品信息
3. **数据一致性**：防止上游传错数据导致后续财务、对账出问题

这是典型的**边界校验**——在系统入口处把好关，避免后续流程出更难排查的问题。
