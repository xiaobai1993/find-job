# 微信充值（非现金）完整流程示意图

## 一、核心ID流转关系说明

```
用户ID(UserId)
   ↓
个人余额账户ID(PersonalBalanceId)
   ↓
充值单ID(RechargeSlipId) 【Payment生成，全局唯一】
   ↓ 传给TPW
TPW Transaction:
   ID = TPW自己生成的主键(雪花ID)
   PaymentSubSlipID = 充值单ID 【Payment传过来的】
   ↓ 传给微信
微信 out_trade_no = TPW Transaction.ID（转字符串）
   ↓ 微信生成
微信 transaction_id = "420000xxxxxx"（微信侧唯一流水号）
   ↓ 微信回调TPW
TPW用Transaction.ID查库，找到PaymentSubSlipID
   ↓ TPW回调Payment
TransactionId = PaymentSubSlipID（充值单ID）
```

**核心设计**：TPW用自己的Transaction.ID作为微信的out_trade_no，而不是直接用Payment的充值单ID。这样TPW可以在内部保持自己的事务独立性，同时通过PaymentSubSlipID关联到Payment侧。

## 二、完整时序流程图（含异步通知）

```mermaid
sequenceDiagram
    autonumber
    actor User as 用户
    participant Front as 前端
    participant Payment as Payment服务
    participant TPW as TPW网关服务
    participant Wechat as 微信支付
    participant PB as PersonalBalance服务
    participant MQ as 消息队列

    Note over User,MQ: ========== 阶段1：创建充值单 + 获取支付参数 ==========

    User->>Front: 点击充值，输入金额100元
    Front->>Payment: POST /recharge<br/>{amount:10000, paymentMethodId:微信ID}
    activate Payment

    Payment->>Payment: 生成充值单ID = 12345 (雪花算法)
    Payment->>PB: ListRechargeMethods(UserId, BalanceId, Amount)
    activate PB
    PB-->>Payment: 返回支持的支付方式列表
    deactivate PB

    Note over Payment: 校验：<br/>- 金额在上下限内<br/>- 币种匹配<br/>- 活动规则一致

    Payment->>Payment: 创建Transaction 【TPW侧】
    Note right of Payment: 调用TPW创建交易<br/>PaymentSubSlipID = 12345

    Payment->>TPW: GetWechatPaymentParams(param)
    activate TPW

    TPW->>TPW: 用GetByPaymentSubSlipID(12345)查询
    alt 已存在Transaction
        TPW->>TPW: 复用已有Transaction
    else 不存在Transaction
        TPW->>TPW: 生成Transaction.ID = 67890<br/>PaymentSubSlipID = 12345<br/>TradeStatus = Pending
        TPW->>TPW: 加PaymentSubSlipID锁防并发
    end

    TPW->>Wechat: 统一下单 UnifiedOrder
    activate Wechat
    Note right of TPW: out_trade_no = "67890" (Transaction.ID转字符串)<br/>total_fee = 10000<br/>trade_type = JSAPI/NATIVE等
    Wechat-->>TPW: prepay_id + 签名参数
    deactivate Wechat

    TPW-->>Payment: 返回微信支付参数(字节数组)
    deactivate TPW

    Payment-->>Front: {rechargeSlipId:12345, payParams: {...}}
    deactivate Payment
    Front->>User: 显示微信支付二维码/唤起微信支付

    Note over User,MQ: ========== 阶段2：用户支付 + 微信异步通知 ==========

    User->>Wechat: 输入密码，确认支付
    activate Wechat
    Wechat-->>User: 支付成功
    deactivate Wechat

    Wechat->>TPW: 支付结果异步通知
    activate TPW
    Note right of Wechat: 【微信回调参数】<br/>out_trade_no = "67890" (TPW Transaction.ID)<br/>transaction_id = "4200001234567890" (微信流水号)<br/>return_code = SUCCESS<br/>result_code = SUCCESS<br/>total_fee = 10000

    TPW->>TPW: 验签 + 解析JSON
    TPW->>TPW: outTradeNo, _ := strconv.ParseInt("67890", 10, 64)
    TPW->>TPW: GetByID(ctx, outTradeNo, TpwWechat, Pay) → 找到ID=67890的Transaction
    TPW->>TPW: Transaction.Status = Success<br/>OutTransactionID = "4200001234567890"<br/>OpenID = "o_xxxxxxxxxx"

    TPW->>MQ: 发送NotifyPayment消息
    activate MQ
    Note right of TPW: 【TPW回调Payment参数】<br/>TransactionId: 12345 (PaymentSubSlipID)<br/>OutTransactionId: "4200001234567890" (微信流水号)<br/>TradeType: Pay<br/>Status: Succeeded<br/>Amount: 10000<br/>TpwType: WECHAT<br/>PaymentScene: JSAPI
    MQ-->>TPW: 发送成功
    deactivate TPW

    Note over User,MQ: ========== 阶段3：Payment处理回调 ==========

    MQ->>Payment: 消费NotifyPayment消息
    activate Payment

    Payment->>Payment: 【加锁】LockRechargeSlip(12345)
    Note right of Payment: 分布式锁，防止并发回调

    Payment->>Payment: GetRechargeSlipById(12345)
    Note right of Payment: POS场景会自旋最多6次等单创建完<br/>防止回调比创建单快导致"单不存在"

    alt 充值单状态=Pay (正常流程)
        Payment->>Payment: 更新充值单状态<br/>Status = Recharge<br/>TpwAccountId = 微信商户配置ID<br/>TpwPayScene = JSAPI<br/>TpwExternalTradeNo = "4200001234567890"<br/>AccountType = 微信<br/>AccountSubType = JSAPI

        Payment->>PB: PersonalBalance.Recharge()
        activate PB
        Note right of Payment: 【调用PB参数】<br/>TransactionId: 12345 (充值单ID)<br/>UserId: 用户ID<br/>PersonalBalanceId: 余额账户ID<br/>Amount: 10000<br/>RechargeScene: 微信在线充值<br/>PaymentMethodType: WECHAT<br/>OutTransactionId: "4200001234567890"<br/>CreatedAt: 充值单创建时间

        PB->>PB: 增加个人余额<br/>生成余额交易记录
        PB-->>Payment: {ResultCode: OK, ActivityAmount: 0}
        deactivate PB

        Payment->>Payment: 更新充值单为终态<br/>Status = Success<br/>CompletedAt = now<br/>ActivityAmount = 0

        Payment->>MQ: 发送RechargeSuccess事件
        activate MQ
        Note right of Payment: 【事件内容】<br/>RechargeSlipId: 12345<br/>UserId: xxx<br/>PersonalBalanceId: xxx<br/>Amount: 10000<br/>AccountType: WECHAT<br/>OutTransactionId: "4200001234567890"
        MQ-->>Payment: 发送成功
        deactivate MQ

    else 充值单状态=Recharge/Success (重复回调)
        Payment->>Payment: 直接返回成功，幂等处理
    else 微信支付失败
        Payment->>Payment: Status = PayFailed<br/>CompletedAt = now
    end
    deactivate Payment

    Note over User,MQ: ========== 异常分支：超时未支付 ==========

    MQ->>Payment: 5分钟后触发超时检查
    activate Payment
    Payment->>Payment: 查询充值单状态
    alt 状态=Pay 且未完成
        Payment->>Payment: 调用TPW.CloseOrder关闭微信订单
        Payment->>Payment: Status = TimeoutClosed<br/>CompletedAt = now
    else 已完成/已支付中
        Payment->>Payment: 什么也不做
    end
    deactivate Payment

    Note over User,MQ: ========== 异常分支：无效回调/重复支付 ==========

    Note over Payment,MQ: 如果收到回调但充值单不存在<br/>且微信显示支付成功 → 说明多支付了<br/>Payment自动发送TPW退款回滚任务
```

## 六、异常场景ID处理矩阵

| 异常场景 | ID处理方式 | 最终结果 |
|---------|-----------|---------|
| **重复回调** | 用RechargeSlipId查单，状态已为Recharge/Success直接返回 | 幂等，不重复处理 |
| **超时未支付** | 用RechargeSlipId查单，Status设为TimeoutClosed，调用TPW.CloseOrder(Transaction.ID=67890) | 订单关闭，可重新发起 |
| **回调比创建快(POS)** | 用RechargeSlipId自旋最多6次，每次500ms等单创建完 | 等单创建完再处理 |
| **无效回调(单不存在但支付成功)** | 用out_trade_no(67890)查到Transaction，用PaymentSubSlipID(12345)发起退款回滚 | 自动退款，防止资金损失 |
| **并发回调** | 用RechargeSlipId加分布式锁，串行处理 | 保证状态一致性 |

## 七、关键设计亮点

### 1. TPW的双层ID设计
- **Transaction.ID**：TPW自己的事务ID，传递给微信作为out_trade_no
- **PaymentSubSlipID**：Payment侧的充值单ID，用于TPW回调Payment时关联

**优势**：
- TPW与Payment解耦，各自维护自己的事务ID体系
- 微信侧只能看到TPW的ID，看不到Payment内部ID，安全性更好
- Payment换ID策略不影响TPW已有的微信订单

### 2. 分级查询策略
- 按PaymentSubSlipID查询：用于幂等和并发控制
- 按Transaction.ID查询：用于微信回调处理

### 3. 分布式锁的两个粒度
- `payment_sub_slip_key_{id}`：Payment侧的锁，用于防止重复创建单
- `transaction_key_{id}`：TPW侧的锁，用于回调处理

这样设计保证了：**Payment和TPW各自有自己的ID体系和锁粒度，同时通过PaymentSubSlipID建立关联**
