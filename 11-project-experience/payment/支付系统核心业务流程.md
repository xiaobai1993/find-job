# 支付系统核心业务流程总结

## 一、支付流程全景

### 1.1 支付主流程

```
┌─────────────┐
│  业务系统   │
└──────┬──────┘
       │ 1. 创建支付请求
       ▼
┌─────────────────────────────────────────────────────────┐
│                   MeicanPay 支付系统                      │
│  ┌───────────────────────────────────────────────────┐  │
│  │  2. 创建支付单                                    │  │
│  │     ├─ 参数校验、幂等检查                          │  │
│  │     ├─ 生成支付单ID (Snowflake)                   │  │
│  │     └─ 初始化状态: PendingProcessing              │  │
│  └──────────────────────────┬────────────────────────┘  │
│                             │                           │
│  ┌──────────────────────────▼────────────────────────┐  │
│  │  3. 构建子支付单                                   │  │
│  │     ├─ 按账户优先级分配金额                        │  │
│  │     ├─ 补贴账户 (按百分比/优先级)                  │  │
│  │     ├─ 企业余额账户                                │  │
│  │     ├─ 个人余额账户                                │  │
│  │     └─ 餐点账户                                    │  │
│  └──────────────────────────┬────────────────────────┘  │
│                             │                           │
│  ┌──────────────────────────▼────────────────────────┐  │
│  │  4. 自动支付 (AutoPay)                             │  │
│  │     ├─ 并行查询各账户可用余额                      │  │
│  │     ├─ 总余额足够 → 并发发起支付                  │  │
│  │     └─ 总余额不足 → 进入待手动支付                 │  │
│  └──────────────────────────┬────────────────────────┘  │
│                             │                           │
│  ┌──────────────────────────▼────────────────────────┐  │
│  │  5. 手动支付 (ManualPay)                           │  │
│  │     ├─ 获取微信/支付宝支付参数                     │  │
│  │     ├─ POS付款码支付 (扫码枪)                      │  │
│  │     └─ H5/JSAPI/小程序支付                         │  │
│  └──────────────────────────┬────────────────────────┘  │
│                             │                           │
│  ┌──────────────────────────▼────────────────────────┐  │
│  │  6. 支付结果处理                                   │  │
│  │     ├─ 全部成功 → Succeeded                       │  │
│  │     ├─ 部分成功 → PartialSucceeded                │  │
│  │     └─ 全部失败 → PendingManualPay / Failed       │  │
│  └──────────────────────────┬────────────────────────┘  │
│                             │                           │
│  ┌──────────────────────────▼────────────────────────┐  │
│  │  7. 通知业务方                                     │  │
│  │     └─ 异步回调支付结果                            │  │
│  └───────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

## 二、退款流程全景

### 2.1 全额退款流程

```
┌─────────────┐
│  业务系统   │
└──────┬──────┘
       │ 1. 发起全额退款
       ▼
┌─────────────────────────────────────────────────────────┐
│                   MeicanPay 支付系统                      │
│  ┌───────────────────────────────────────────────────┐  │
│  │  2. 校验参数                                       │  │
│  │     ├─ 是否已全额退款                              │  │
│  │     └─ 计算可退金额 = 已支付金额 - 已退款金额      │  │
│  └──────────────────────────┬────────────────────────┘  │
│                             │                           │
│  ┌──────────────────────────▼────────────────────────┐  │
│  │  3. 处理Pending状态支付单                          │  │
│  │     ├─ 对所有Pending支付单加锁                    │  │
│  │     ├─ 二次刷新状态确认                           │  │
│  │     ├─ 更新Pending主单为 FullRefundClosed         │  │
│  │     └─ 更新Pending子单为 Failed                   │  │
│  └──────────────────────────┬────────────────────────┘  │
│                             │                           │
│  ┌──────────────────────────▼────────────────────────┐  │
│  │  4. 处理后付订单                                   │  │
│  │     └─ 取消微信支付分等后付授权订单                │  │
│  └──────────────────────────┬────────────────────────┘  │
│                             │                           │
│  ┌──────────────────────────▼────────────────────────┐  │
│  │  5. 构建退款单                                     │  │
│  │     ├─ 创建退款单 (FullRefund = true)             │  │
│  │     └─ 为每个已成功子支付单创建退款子单            │  │
│  └──────────────────────────┬────────────────────────┘  │
│                             │                           │
│  ┌──────────────────────────▼────────────────────────┐  │
│  │  6. 发起退款                                       │  │
│  │     ├─ 补贴/余额账户: 同步退款                     │  │
│  │     └─ 微信/支付宝等: 异步退款 + 等待回调          │  │
│  └──────────────────────────┬────────────────────────┘  │
│                             │                           │
│  ┌──────────────────────────▼────────────────────────┐  │
│  │  7. 退款完成                                       │  │
│  │     ├─ 所有子单成功 → 退款单Succeeded              │  │
│  │     └─ 发送退款成功通知给业务方                    │  │
│  └───────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

│  └──────────────────────────┬────────────────────────┘  │
│                             │                           │
│  ┌──────────────────────────▼────────────────────────┐  │

## 五、关键业务规则总结

### 5.1 支付规则

| 规则 | 说明 |
|------|------|
| 账户优先级 | 补贴 > 企业余额 > 个人余额 > 餐点 > 第三方支付 |
| 百分比分配 | 补贴账户支持按百分比分配支付金额 |
| 支付超时 | 每个支付单有独立的Deadline，超时自动关闭 |
| 部分支付 | 支持部分支付成功，剩余金额走手动支付 |

### 5.2 退款规则

| 规则 | 说明 |
|------|------|
| 全额退款 | 可退所有已支付金额，同时关闭所有待支付尝试 |
| 部分退款 | 可退指定金额，支持多次退款直到金额为0 |
| 退款优先级 | 与支付优先级相反，低优先级账户先退款 |
| 菜品校验 | 外卖业务部分退款必须传菜品，且数量不能超退 |
| 退款时效 | 有退款截止时间，超时后不允许退款 |

### 5.3 后付规则

| 规则 | 说明 |
|------|------|
| 授权模式 | 用户先授权额度，消费后统一结算 |
| 取消机制 | 全额退款时自动取消后付授权订单 |
| 支持渠道 | 目前仅支持微信支付分 |

## 六、异常处理机制

### 6.1 支付异常

| 异常场景 | 处理策略 |
|---------|---------|
| 账户余额不足 | 进入待手动支付状态 |
| 第三方渠道超时 | 状态保持Pending，等待回调或重试 |
| 部分子单失败 | 支付单状态为 PartialSucceeded，剩余金额可手动支付 |
| 网络异常 | 基于幂等性保证，支持重试 |

### 6.2 退款异常

| 异常场景 | 处理策略 |
|---------|---------|
| 第三方渠道退款失败 | 记录失败状态，人工介入 |
| 部分子单退款成功 | 更新已退金额，剩余子单继续重试 |
| 并发退款 | 分布式锁保护，防止重复退款 |

## 七、通知机制

### 7.1 通知类型

| 通知类型 | 触发时机 | 接收方 |
|---------|---------|--------|
| 支付成功通知 | 支付单全部支付完成 | 业务系统 |
| 支付失败通知 | 支付单最终失败 | 业务系统 |
| 退款成功通知 | 退款单全部退款完成 | 业务系统 |
| 子单完成通知 | 单个子支付/退款单完成 | 内部对账系统 |

### 7.2 通知保障

- **至少一次投递**：消息队列保证不丢失
- **幂等处理**：接收方需要处理重复通知
- **重试机制**：失败后自动重试，有退避策略
