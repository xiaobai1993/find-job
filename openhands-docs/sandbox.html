沙箱环境 · 安全隔离

OpenHands 沙箱环境机制

三种运行模式，从本地开发到企业级多租户部署，为 AI Agent 提供安全、隔离、可扩展的执行环境。

🖥️ 本地模式 🐳 Docker 模式 ☸️ Kubernetes 模式
设计理念

为什么需要沙箱？

AI Agent 会真实地执行代码和命令，沙箱是安全运行的基石。

1

安全隔离

Agent 生成的代码可能存在风险——误删文件、安装恶意包、访问敏感数据。沙箱将 Agent 的执行环境与宿主系统完全隔离，即使出现问题也不会扩散。

2

环境一致性

每个会话都在干净、可复现的环境中开始。预装了常用开发工具链，确保 Agent 的执行结果可预测，不会因"我这里可以跑"而出错。

3

资源管控

通过容器或 Pod 的资源限制（CPU、内存、磁盘），防止 Agent 的无限循环或内存泄漏耗尽宿主资源，保障系统整体稳定性。

4

多租户隔离

在企业或云服务场景下，不同用户的 Agent 会话运行在完全独立的沙箱中，数据互不可见，满足安全合规要求。

模式一

🖥️ 本地模式 (Local Mode)

最简单的运行方式，直接在本机运行，适合开发调试和个人使用。

工作原理

本地模式下，OpenHands 的 Agent 进程直接运行在宿主机上，文件系统、网络、进程都与宿主共享。 Agent 通过子进程（如 bash、python）执行命令，读写宿主文件系统。

使用方式

# 安装 OpenHands
pip install openhands

# 直接运行（默认本地模式）
openhands

# 或显式指定
openhands --sandbox local

优缺点

✅ 优点

  • 零配置，开箱即用
  • 性能最好，无虚拟化开销
  • 可直接使用宿主已安装的所有工具
  • 调试方便，问题易定位

❌ 缺点

  • 无隔离：Agent 可能误删文件或破坏系统
  • 无资源限制，可能耗尽宿主资源
  • 不适合多用户场景
  • 环境不一致，依赖宿主配置
⚠️ 安全提示：本地模式下 Agent 拥有与启动用户相同的权限， 请勿在生产环境或不信任的任务中使用。仅推荐用于本地开发、调试和可信的个人使用场景。
模式二

🐳 Docker 模式 (Docker Mode)

推荐的标准运行方式，每个会话一个独立容器，兼顾安全性与易用性。

工作原理

Docker 模式下，OpenHands 为每个 Agent 会话创建一个独立的 Docker 容器。 容器内预装了完整的开发环境（Python、Node.js、Git 等工具链），Agent 在容器内执行所有操作。 通过 Docker API 实现容器生命周期管理和文件同步。

关键特性

📦 会话级隔离

每个会话一个容器，会话结束容器销毁。环境干净，互不干扰。

🔄 文件双向同步

宿主与容器间通过文件同步机制交换代码和数据，支持热更新。

🛠 预装开发环境

官方镜像预装 Python、Node.js、Go、Java、Git 等常用工具，开箱即用。

📈 资源限制

通过 Docker cgroup 限制每个容器的 CPU、内存使用，防止资源耗尽。

🧩 自定义镜像

支持自定义 Docker 镜像，可按需预装特定语言、框架或内部工具。

🔌 端口转发

支持将容器内端口映射到宿主，便于 Agent 开发的 Web 服务预览。

使用方式

# 确保 Docker 已启动
docker info

# Docker 模式启动（推荐）
openhands --sandbox docker

# 指定自定义镜像
openhands --sandbox docker --base-image my-custom-openhands:latest

# 限制资源
openhands --sandbox docker \
  --docker-cpu-limit 2 \
  --docker-memory-limit 4g

💡 提示：Docker 模式是 OpenHands 的默认推荐模式， 适合大多数个人和小团队场景。对于需要多租户、大规模部署的企业用户，建议使用 Kubernetes 模式。
模式三

☸️ Kubernetes 模式 (K8s Mode)

企业级部署方案，每个会话一个 Pod，支持多租户、水平扩展与精细权限管控。

工作原理

Kubernetes 模式下，OpenHands 通过 K8s API 在集群中为每个会话创建独立的 Pod。 这是最强大的部署模式——支持资源配额、网络策略、持久化存储、自动伸缩等企业级特性。 OpenHands Enterprise 版本就是基于此模式构建的多租户 SaaS 平台。

核心架构组件

🎛 控制平面 (Control Plane)

OpenHands 的 API 服务运行在集群中，负责接收会话请求、调度 Pod、 管理生命周期、收集日志与指标。它相当于集群中的"大脑"。

📦 会话 Pod (Session Pod)

每个用户会话对应一个 Pod，Pod 内可包含多个容器（sidecar 模式）： Agent 主容器 + 执行环境容器 + 日志/监控 sidecar。 Pod 之间完全隔离，各自拥有独立的网络和文件系统。

📊 资源管控 (Resource Management)

通过 ResourceQuota 和 LimitRange 限制每个命名空间、 每个 Pod 的 CPU、内存、存储使用。结合 HPA (Horizontal Pod Autoscaler) 可自动扩缩容。

🔒 网络策略 (NetworkPolicy)

使用 K8s NetworkPolicy 精细控制每个 Pod 的网络访问—— 哪些可以出公网、哪些只能访问内部服务、哪些完全隔离。 满足企业安全合规要求。

💾 存储管理 (Storage)

通过 PersistentVolumeClaim (PVC) 为会话提供持久化存储， 用户代码和数据可以在会话间保留。也支持空目录（会话即销毁）的无状态模式。

👤 多租户隔离 (Multi-tenancy)

每个租户 / 团队使用独立的 Namespace，配合 RBAC、NetworkPolicy、 ResourceQuota 实现硬隔离。OpenHands Enterprise 进一步提供 SSO 集成、 审计日志、用量计量等企业特性。

使用方式

# 使用 Helm 部署 OpenHands 到 K8s 集群
helm repo add openhands https://charts.all-hands.dev
helm install openhands openhands/openhands \
  --namespace openhands \
  --create-namespace \
  --set sandbox.kubernetes.enabled=true

# 配置资源限制（values.yaml 示例）
sandbox:
  kubernetes:
    enabled: true
    namespace: openhands-sessions
    resources:
      limits:
        cpu: "2"
        memory: "4Gi"
      requests:
        cpu: "500m"
        memory: "1Gi"
    storage:
      enabled: true
      size: 10Gi
    networkPolicy:
      enabled: true
      allowEgress: true

# 查看会话 Pod
kubectl get pods -n openhands-sessions
✅ 适用场景：企业内部 AI 编程平台、多团队共享环境、 需要强安全隔离的研发场景、面向客户的 SaaS 服务。
进阶

🚢 多容器部署与高级模式

当单个容器不足以满足需求时，OpenHands 支持更复杂的多容器编排方案。

为什么需要多容器？

有些场景下，Agent 不仅仅需要一个 shell 环境——它可能需要连接数据库、 调用微服务、使用浏览器进行端到端测试、或者运行需要多个进程协作的应用。 这时候就需要多容器环境来支撑。

🔗

Sidecar 模式

主 Agent 容器 + 辅助 sidecar 容器（如浏览器、代理、日志收集）。 共享网络命名空间，通过 localhost 互相通信。

agent browser proxy
🎯

服务依赖模式

Agent 容器 + 依赖服务容器（如 PostgreSQL、Redis、MySQL）。 Agent 可以真实地连接和操作数据库，进行数据库开发和测试。

agent postgres redis
🌐

微服务模式

模拟完整的微服务环境，多个应用容器 + Agent 容器。 Agent 可以在类生产环境中开发、测试和调试分布式系统。

agent api-svc auth-svc db
🧪

E2E 测试模式

Agent + 应用服务 + 浏览器（Playwright/Puppeteer）。 Agent 编写代码后，可以自动启动应用并运行端到端测试验证。

agent web-app browser

Docker Compose 中的多容器

对于 Docker 模式，也可以通过自定义 compose 文件实现多容器环境： 

# docker-compose.yml 示例
services:
  openhands-agent:
    image: ghcr.io/all-hands-ai/openhands:latest
    depends_on:
      - postgres
      - redis
    environment:
      - DATABASE_URL=postgres://user:pass@postgres:5432/app
      - REDIS_URL=redis://redis:6379

  postgres:
    image: postgres:16-alpine
    environment:
      - POSTGRES_PASSWORD=pass

  redis:
    image: redis:7-alpine

关键技术要点

📡 服务发现

K8s 中通过 DNS（service-name.namespace.svc.cluster.local）互相发现；Docker 模式下通过 compose 的默认网络。

📂 数据共享

Pod 内容器共享 emptyDir 卷或 PVC；Docker 中使用共享 volume。Agent 与执行环境通过共享目录交换文件。

⏱ 生命周期绑定

所有辅助容器与会话生命周期绑定——会话开始时创建，结束时一并销毁，无残留。

🔌 端口暴露

Agent 开发的 Web 服务可通过 Service + Ingress 或端口转发访问，支持实时预览。

🎛 资源调度

K8s 根据 Pod 总资源需求调度到合适的节点，支持节点亲和性、污点容忍等高级调度策略。

🔐 安全加固

每个容器可独立配置 SecurityContext——非 root 用户、只读根文件系统、seccomp/AppArmor 配置。

决策指南

我该选择哪种模式？

你是个人开发者，本地使用？
✅ 是 → 本地模式 或 Docker 模式
❌ 否 → 继续
小团队共享，需要一定隔离？
✅ 是 → Docker 模式（单机部署）
❌ 否 → 继续
企业级部署 / 多租户 / 需要高可用？
✅ 是 → Kubernetes 模式
❌ 否 → 根据实际规模选择
Agent 需要数据库/浏览器等依赖服务？
✅ 是 → Docker Compose 或 K8s 多容器 Pod
