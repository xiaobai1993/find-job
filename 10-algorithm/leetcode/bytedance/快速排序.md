# 快速排序

> 字节跳动高频面试题，要求手写快排并分析复杂度

---

## 一、算法思想

快速排序的核心是**分治**：

1. **选基准（pivot）**：从数组中选一个元素作为基准
2. **分区（partition）**：把比 pivot 小的放左边，比 pivot 大的放右边
3. **递归**：对左右两个子数组重复上述过程

图解 `[5, 3, 8, 6, 2, 7, 1, 4]`，选最后一个元素 4 作为 pivot：

```
原始:  [5, 3, 8, 6, 2, 7, 1, 4]
                      ↑        ↑
                   i 指针    pivot=4

分区过程（i 记录小于 pivot 的边界）：
  5 > 4, 跳过       → [5, 3, 8, 6, 2, 7, 1, 4]
  3 < 4, swap(5,3)  → [3, 5, 8, 6, 2, 7, 1, 4]
  8 > 4, 跳过       → 同上
  6 > 4, 跳过       → 同上
  2 < 4, swap(5,2)  → [3, 2, 8, 6, 5, 7, 1, 4]
  7 > 4, 跳过       → 同上
  1 < 4, swap(8,1)  → [3, 2, 1, 6, 5, 7, 8, 4]

最后 swap(6, 4) 把 pivot 放到正确位置：
  → [3, 2, 1, 4, 5, 7, 8, 6]
              ↑
           pivot 落位（索引 3）

递归处理左边 [3,2,1] 和右边 [5,7,8,6]
```

## 二、Go 实现

### 基础版本（Lomuto 分区）

```go
package main

import "fmt"

func quickSort(arr []int, left, right int) {
    if left >= right {
        return
    }
    pivotIdx := partition(arr, left, right)
    quickSort(arr, left, pivotIdx-1)
    quickSort(arr, pivotIdx+1, right)
}

// Lomuto 分区：选最后一个元素为 pivot
func partition(arr []int, left, right int) int {
    pivot := arr[right]
    i := left // i 指向小于 pivot 区域的末尾

    for j := left; j < right; j++ {
        if arr[j] < pivot {
            arr[i], arr[j] = arr[j], arr[i]
            i++
        }
    }
    // pivot 放到正确位置
    arr[i], arr[right] = arr[right], arr[i]
    return i
}

func main() {
    arr := []int{5, 3, 8, 6, 2, 7, 1, 4}
    quickSort(arr, 0, len(arr)-1)
    fmt.Println(arr) // [1 2 3 4 5 6 7 8]
}
```

### 优化版本（三路快排 + 随机化 pivot）

处理大量重复元素时，三路快排将数组分为 `< pivot`、`= pivot`、`> pivot` 三部分，避免重复元素被反复分区：

```go
package main

import (
    "fmt"
    "math/rand"
)

func quickSort3Way(arr []int, left, right int) {
    if left >= right {
        return
    }
    // 随机化 pivot，避免最坏情况
    randIdx := left + rand.Intn(right-left+1)
    arr[left], arr[randIdx] = arr[randIdx], arr[left]

    pivot := arr[left]
    lt, i, gt := left, left+1, right

    // [left..lt-1] < pivot
    // [lt..gt]     = pivot
    // [gt+1..right] > pivot
    for i <= gt {
        if arr[i] < pivot {
            arr[i], arr[lt] = arr[lt], arr[i]
            lt++
            i++
        } else if arr[i] > pivot {
            arr[i], arr[gt] = arr[gt], arr[i]
            gt--
            // i 不动，因为交换过来的元素还没检查
        } else {
            i++
        }
    }
    quickSort3Way(arr, left, lt-1)
    quickSort3Way(arr, gt+1, right)
}

func main() {
    arr := []int{5, 3, 8, 6, 2, 7, 1, 4, 4, 4, 4}
    quickSort3Way(arr, 0, len(arr)-1)
    fmt.Println(arr) // [1 2 3 4 4 4 4 5 6 7 8]
}
```

## 三、复杂度分析

### 时间复杂度

| 情况 | 复杂度 | 说明 |
|------|--------|------|
| 最好 | O(n log n) | 每次 pivot 恰好把数组等分，递归树高度 log n，每层比较 n 次 |
| 平均 | O(n log n) | 随机输入下，期望递归深度 log n |
| 最坏 | O(n²) | 数组已有序 + 选首/尾做 pivot，每次只减少一个元素 |

最坏情况图示（已排序数组，选最后元素为 pivot）：

```
[1, 2, 3, 4, 5, 6, 7, 8]  pivot=8, 分区后只分出左边
[1, 2, 3, 4, 5, 6, 7]     pivot=7
[1, 2, 3, 4, 5, 6]        pivot=6
...
→ n + (n-1) + (n-2) + ... + 1 = O(n²)
```

**优化方法**：随机化 pivot 或三数取中，把最坏情况概率降到极低，工程上视为 O(n log n)。

### 空间复杂度

| 情况 | 复杂度 | 说明 |
|------|--------|------|
| 最好 | O(log n) | 等分时递归深度 log n |
| 平均 | O(log n) | 随机输入下递归深度期望 log n |
| 最坏 | O(n) | 退化为链式递归，深度 n |

> 快排是**原地排序**（in-place），不需要额外数组，空间消耗完全来自递归调用栈。

## 四、快排 vs 其他排序

| 排序算法 | 平均时间 | 最坏时间 | 空间 | 稳定性 |
|----------|----------|----------|------|--------|
| 快速排序 | O(n log n) | O(n²) | O(log n) | 不稳定 |
| 归并排序 | O(n log n) | O(n log n) | O(n) | 稳定 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | 不稳定 |
| Tim Sort | O(n log n) | O(n log n) | O(n) | 稳定 |

**快排为什么实际最快？**

- 常数因子小：内循环紧凑，比较+交换在缓存友好的连续内存上完成
- 缓存友好：顺序扫描数组，局部性好
- 尾递归优化：可优化一侧递归为迭代，栈深度降到 O(log n)

**什么时候不用快排？**

- 要求稳定排序 → 用归并排序 / Tim Sort
- 数据量极小 → 插入排序更优（Go 标准库 sort 在小块时切插入排序）
- 内存受限 → 堆排序 O(1) 额外空间

## 五、面试常见追问

**Q1: 为什么随机化能避免最坏情况？**

随机化后，每次选到极端 pivot 的概率是 1/n，连续多次选到极端 pivot 的概率指数级衰减，数学期望仍为 O(n log n)。

**Q2: Go 标准库的 sort 用的是什么？**

`sort.Sort` 使用的是 **pdqsort**（Pattern-Defeating Quicksort），结合了快排、堆排序、插入排序的优点：
- 对小片段切插入排序
- 发现快排退化时切堆排序（保证最坏 O(n log n)）
- 对已有序/逆序的输入有专门优化

**Q3: 快排稳定性能优化到稳定吗？**

不能。快排的交换操作会改变相等元素的相对顺序。要稳定排序需要额外空间记录原始索引（本质变成归并），得不偿失。

**Q4: Hoare 分区 vs Lomuto 分区？**

| 对比项 | Lomuto | Hoare |
|--------|--------|-------|
| 指针 | 单指针 i | 双指针 left/right |
| 交换次数 | 较多 | 较少 |
| 实现难度 | 简单 | 稍复杂 |
| 性能 | 略慢 | 更快（少 3 倍交换） |

Hoare 分区从两端向中间扫描，交换逆序对，指针相遇时分区完成。
