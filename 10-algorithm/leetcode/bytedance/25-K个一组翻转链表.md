# 25. K 个一组翻转链表

题目链接：`https://leetcode.cn/problems/reverse-nodes-in-k-group/description/`

---

## 一、题目描述

给一个链表，每 k 个节点一组翻转，末尾不足 k 个的不翻转。

**示例：**

```
输入: 1→2→3→4→5, k=2
输出: 2→1→4→3→5

输入: 1→2→3→4→5, k=3
输出: 3→2→1→4→5   （4→5不足3个，不翻转）
```

---

## 二、核心思路：递归拆解

这题的递归思路极其优雅，一句话概括：

> **先翻转前 k 个，剩下的交给递归。**

把大问题拆成：翻转当前组 + 递归处理剩余部分。不需要 dummy 节点，不需要迭代管理 groupTail，递归天然处理了"组与组之间的连接"。

拆成两个函数：

| 函数 | 职责 |
|------|------|
| `reverseKGroup(head, k)` | 递归主函数：翻转前 k 个，递归处理剩余 |
| `reverse(a, b)` | 翻转 `[a, b)` 区间（左闭右开），返回新头 |

---

## 三、先搞懂 reverse(a, b)

这是基础操作，和普通翻转链表一模一样，唯一的区别是**终止条件不是 `curr != nil`，而是 `curr != tail`**。

也就是说，翻转的是 `[a, b)` 这个左闭右开区间，`b` 本身不参与翻转。

```
翻转 [1, 4)，即翻转 1→2→3，4 不动

初始: pre=nil, cur=1, tail=4

第1步: cur=1, temp=2
       1→nil, pre=1, cur=2
       1

第2步: cur=2, temp=3
       2→1, pre=2, cur=3
       2→1

第3步: cur=3, temp=4
       3→2→1, pre=3, cur=4
       3→2→1

cur=4 == tail，停止
返回 pre=3（翻转后的头）
```

关键点：翻转后 `1.Next = nil`（因为 pre 初始是 nil），**`a` 变成了翻转后的尾**，它的 Next 被断开了。

代码：

```go
// 翻转 [a, b) 区间，左闭右开
func reverse(a, b *ListNode) *ListNode {
    var pre *ListNode
    cur := a
    for cur != b {
        temp := cur.Next
        cur.Next = pre
        pre = cur
        cur = temp
    }
    return pre
}
```

为什么用左闭右开 `[a, b)`？因为 `b` 恰好就是下一组的起点，这样 `reverse` 翻转完一组后，`cur` 自然停在了下一组的头，不用额外计数。

## 四、递归主函数 reverseKGroup

```go
func reverseKGroup(head *ListNode, k int) *ListNode {
    if head == nil {
        return nil
    }
    // 1. b 走 k 步，定位下一组的起点
    a, b := head, head
    for i := 0; i < k; i++ {
        if b == nil {
            return a // 不足 k 个，不翻转，直接返回头
        }
        b = b.Next
    }

    // 2. 翻转 [a, b)，即翻转前 k 个
    newHead := reverse(a, b)

    // 3. a 翻转后变成了尾，接上递归结果
    a.Next = reverseKGroup(b, k)

    // 4. 返回翻转后的头
    return newHead
}
```

三步走：

```
1. b 走 k 步    →  确定当前组 [a, b)，同时检查够不够 k 个
2. reverse(a,b) →  翻转当前组，a 变成尾，newHead 是新头
3. a.Next = 递归 →  尾巴接上剩余部分翻转的结果
```

## 五、完整流程图解

### 例1：`1→2→3→4→5, k=2`

```
reverseKGroup(1, 2)
├── a=1, b走2步 → b=3（够2个）
├── newHead = reverse(1, 3) = 2
│   翻转后: 2→1→nil（1.Next 断开了）
├── a.Next = reverseKGroup(3, 2)
│   ├── a=3, b走2步 → b=5（够2个）
│   ├── newHead = reverse(3, 5) = 4
│   │   翻转后: 4→3→nil
│   ├── a.Next = reverseKGroup(5, 2)
│   │   ├── a=5, b走2步 → i=0: b=5→nil, i=1: b=nil
│   │   └── return 5（不足2个，不翻转）
│   ├── a.Next = 5 → 4→3→5
│   └── return 4
├── a.Next = 4 → 2→1→4→3→5
└── return 2

结果: 2→1→4→3→5 ✓
```

### 例2：`1→2→3→4→5, k=3`

```
reverseKGroup(1, 3)
├── a=1, b走3步 → b=4（够3个）
├── newHead = reverse(1, 4) = 3
│   翻转后: 3→2→1→nil
├── a.Next = reverseKGroup(4, 3)
│   ├── a=4, b走3步 → i=0: b=5, i=1: b=nil
│   └── return 4（不足3个，不翻转）
├── a.Next = 4 → 3→2→1→4→5
└── return 3

结果: 3→2→1→4→5 ✓
```

## 六、为什么不需要 dummy 节点？

迭代法需要 dummy 是因为翻转第一组后头节点变了，需要统一处理。

递归法不需要，因为**每一层递归天然返回的就是当前组的头**，上一层通过 `a.Next = reverseKGroup(b, k)` 接上就行。第一层返回的 `newHead` 就是整个链表的新头。

对比：

| | 迭代法 | 递归法 |
|--|--------|--------|
| 连接方式 | groupTail.Next = newHead | a.Next = 递归结果 |
| 需要dummy | 是，统一处理头节点变化 | 否，递归天然处理 |
| 管理状态 | groupTail 需要手动更新 | 递归栈自动管理 |

## 七、Go 完整代码

```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func reverseKGroup(head *ListNode, k int) *ListNode {
    if head == nil {
        return nil
    }
    // b 走 k 步，定位下一组的起点
    a, b := head, head
    for i := 0; i < k; i++ {
        if b == nil {
            return a // 不足 k 个，不翻转
        }
        b = b.Next
    }

    // 翻转 [a, b)，a 变成尾
    newHead := reverse(a, b)

    // 尾巴接上递归结果
    a.Next = reverseKGroup(b, k)

    return newHead
}

// 翻转 [a, b) 区间
func reverse(a, b *ListNode) *ListNode {
    var pre *ListNode
    cur := a
    for cur != b {
        temp := cur.Next
        cur.Next = pre
        pre = cur
        cur = temp
    }
    return pre
}
```

## 八、逐行理解

### reverseKGroup 主函数

```go
if head == nil { return nil }   // 空链表，递归终点

a, b := head, head              // a=当前组头, b=用来走步的指针
for i := 0; i < k; i++ {
    if b == nil {
        return a                // 走不到 k 步，不足，直接返回头（不翻转）
    }
    b = b.Next                  // b 往前走
}
// 循环结束：b 指向第 k+1 个节点（下一组的头）

newHead := reverse(a, b)        // 翻转 [a,b)，newHead 是新头，a 变成尾

a.Next = reverseKGroup(b, k)    // 关键：a 是翻转后的尾，接上递归结果

return newHead                  // 返回当前组的头
```

### reverse(a, b) 辅助函数

```go
var pre *ListNode               // pre 初始 nil → 翻转后 a.Next=nil（断开）
cur := a
for cur != b {                  // 左闭右开，b 不参与
    temp := cur.Next            // 先保存下一个
    cur.Next = pre              // 翻转指针
    pre = cur                   // pre 前进
    cur = temp                  // cur 前进
}
return pre                      // pre 就是翻转后的头
```

## 九、复杂度分析

- **时间**：O(n)，每个节点只被访问一次（b 走步 + reverse 各访问一次，但总共还是 O(n)）
- **空间**：O(n/k)，递归栈深度 = 组数 = n/k

---

## 十、容易错的点

### 1. b 走 k 步，不是走 k-1 步

```go
// b 走 k 步后，b 指向第 k+1 个节点
// reverse(a, b) 翻转的是 [a, b)，刚好 k 个
for i := 0; i < k; i++ {
    if b == nil { return a }
    b = b.Next
}
```

如果写成 `i < k-1`，`b` 只走到第 k 个节点，`reverse(a, b)` 只翻转了 k-1 个。

### 2. 不足 k 个时 return a，不是 return head

`a` 和 `head` 值相同，但语义上 return `a` 更清晰——返回当前组的头，不做翻转。

### 3. a.Next = 递归结果，这行是精髓

翻转后 `a` 变成了尾（`a.Next = nil`），必须接上递归结果：

```go
// ✓ 翻转后，a 是尾，接上递归结果
a.Next = reverseKGroup(b, k)

// ✗ 如果不接，链表在 a 处断了
```

### 4. reverse(a, b) 是左闭右开

`b` 不参与翻转。这个设计让 `b` 天然是下一组的起点，不用额外保存。

### 5. 递归 vs 迭代的取舍

递归写法简洁，但空间 O(n/k)。面试时两种都能写，递归更容易一次写对。如果面试官追问空间优化，再写迭代版。

---

## 十一、面试表达

> 每 k 个一组翻转链表。用递归：先用 b 指针走 k 步确定一组，不够 k 个就直接返回不翻转。够的话，用 reverse 翻转 [a, b) 区间，翻转后 a 变成尾，a.Next 接上递归处理剩余部分的结果。reverse 就是经典头插法，终止条件从 cur!=nil 改成 cur!=b。时间 O(n)，空间 O(n/k) 是递归栈。
