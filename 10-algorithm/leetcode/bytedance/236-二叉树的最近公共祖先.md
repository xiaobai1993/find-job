# 236. 二叉树的最近公共祖先

题目链接：`https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree/`

---

## 一、题目描述

给定一个二叉树，找到该树中两个指定节点的最近公共祖先。

**最近公共祖先**：对于有根树 T 的两个节点 p、q，最近公共祖先表示一个节点 x，满足 x 是 p、q 的祖先且 x 的深度尽可能大（一个节点也可以是它自己的祖先）。

**示例 1：**

```
        3
       / \
      5   1
     / \ / \
    6  2 0  8
      / \
     7   4

输入: root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 1
输出: 3
解释: 节点 5 和 1 的最近公共祖先是 3。
```

**示例 2：**

```
        3
       / \
      5   1
     / \ / \
    6  2 0  8
      / \
     7   4

输入: root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 4
输出: 5
解释: 节点 5 和 4 的最近公共祖先是 5，因为根据定义，一个节点可以是自己的祖先。
```

---

## 二、核心思路：后序遍历 + 自底向上

**公共祖先的本质**：从根往下走，第一次"分叉"的节点就是最近公共祖先。

```
情况1：p 和 q 分布在两侧
        LCA
       /   \
      p     q

情况2：p 是 q 的祖先（或反过来）
        p (= LCA)
       / \
      ... q

情况3：q 是 p 的祖先（或反过来）
        q (= LCA)
       / \
      p ...
```

这三种情况可以统一处理：**后序遍历，自底向上找，某个节点的左子树找到了 p/q，右子树也找到了 p/q，那它就是 LCA。**

---

## 三、递归解法

```go
func lowestCommonAncestor(root, p, q *TreeNode) *TreeNode {
    // base case：越界或找到了 p/q
    if root == nil || root == p || root == q {
        return root
    }

    left := lowestCommonAncestor(root.Left, p, q)
    right := lowestCommonAncestor(root.Right, p, q)

    // 左右都找到了 → 当前节点就是 LCA
    if left != nil && right != nil {
        return root
    }

    // 只有一边找到了，返回那边（p/q 都在那棵子树里）
    if left != nil {
        return left
    }
    return right
}
```

---

## 四、逐行理解

### 1. 终止条件

```go
if root == nil || root == p || root == q {
    return root
}
```

三种情况返回当前节点：
- `root == nil`：到底了，返回 nil
- `root == p`：找到了 p，返回 p（同时告诉上层"我这棵子树有目标节点"）
- `root == q`：同上

### 2. 后序：先递归左右子树

```go
left := lowestCommonAncestor(root.Left, p, q)
right := lowestCommonAncestor(root.Right, p, q)
```

后序遍历保证：先看子树的结果，再决定当前节点是什么。

### 3. 判断逻辑

```go
if left != nil && right != nil {
    return root       // 情况1：p、q 分居两侧，当前就是 LCA
}
if left != nil {
    return left       // 左边有结果，返回左边
}
return right          // 右边有结果，返回右边（可能为 nil）
```

为什么只返回非 nil 那边？因为 `left` 和 `right` 只有三种可能：
- 找到了 p 或 q（返回的就是 p/q 本身）
- 找到了 LCA（更深的祖先已经确定了）
- nil（这棵子树啥也没有）

把非 nil 的往上传递，上层就能做判断。

## 五、完整流程图解

以示例 1 为例，`p = 5, q = 1`：

```
        3
       / \
      5   1
     / \ / \
    6  2 0  8
      / \
     7   4
```

后序遍历的递归过程：

```
dfs(3)
├── dfs(5)          → 5 == p，直接返回 5
├── dfs(1)          → 1 == q，直接返回 1
└── left=5, right=1 → 都非 nil，返回 root=3  ← LCA!
```

再看示例 2，`p = 5, q = 4`：

```
dfs(3)
├── dfs(5)           → 5 == p，直接返回 5？不急，还得看子树
│   ├── dfs(6)       → nil
│   ├── dfs(2)
│   │   ├── dfs(7)   → nil
│   │   ├── dfs(4)   → 4 == q，返回 4
│   │   └── left=nil, right=4 → 返回 4
│   └── left=nil, right=2→4
│       等等，5 == p 直接返回了，不会进入子树！
│       因为 root == p 触发终止条件
│   所以 dfs(5) 直接返回 5
├── dfs(1) → 子树里没有 p 也没有 q → 返回 nil
└── left=5, right=nil → 返回 left=5  ← LCA!
```

关键点：**`root == p` 时直接返回，不会再往下搜索**。这正好对应"一个节点可以是自己的祖先"。

## 六、为什么是后序不是前序？

```
前序（自顶向下）：到了一个节点，你还不知道子树里有没有 p/q，无法判断
后序（自底向上）：到了一个节点，左右子树的结果已经知道了，可以判断
```

所以这道题**必须后序**。前序做不到。

## 七、复杂度分析

| 维度 | 值 |
|------|------|
| 时间 | O(n)，最坏遍历所有节点 |
| 空间 | O(h)，递归栈深度，h 为树高，最坏 O(n)（链状） |

## 八、容易错的点

### 1. 终止条件是 `root == p || root == q`，不是 `root.Val == p.Val`

比较的是**节点引用**，不是值。题目保证 p、q 在树中存在。

### 2. 一个节点可以是自己的祖先

`p = 5, q = 4` 时，5 就是答案。代码天然处理了这种情况：`root == p` 直接返回 p，上层发现另一边是 nil，就把 p 往上传递，最终 p 就是结果。

### 3. 只有一边非 nil 时，返回非 nil 那边

```go
if left != nil {
    return left
}
return right  // right 可能是 nil，没关系
```

不要写成：

```go
// 错！左右都是 nil 的情况你没处理
if left != nil && right == nil {
    return left
}
if left == nil && right != nil {
    return right
}
// 左右都是 nil → 没有返回值，编译报错
```

### 4. 和 BST 的 LCA 区分

如果是 BST（LeetCode 235），可以利用有序性：p、q 值都小于当前节点则往左，都大于则往右，否则就是当前节点。**本题是普通二叉树，没有有序性，必须搜索。**

## 九、变体：带父指针怎么优化？

如果每个节点有 `parent` 指针，问题等价于**两个链表找交点**（LeetCode 160）：

```
p 到根的路径：p → ... → LCA → ... → root
q 到根的路径：q → ... → LCA → ... → root
```

从 p、q 往上走，第一个交点就是 LCA。用 hash set 记录 p 的祖先路径，q 往上走时查 set 即可。

---

## 十、面试表达

> 找最近公共祖先，用后序遍历自底向上。递归函数返回当前子树中是否包含 p 或 q：如果左右子树分别找到了 p 和 q，当前节点就是 LCA；如果只有一边找到了，就把结果往上传递；如果 root 本身就是 p 或 q，直接返回它。时间 O(n)，空间 O(h)。
