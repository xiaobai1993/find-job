# 23. 合并 K 个升序链表

题目链接：`https://leetcode.cn/problems/merge-k-sorted-lists/description/`

---

## 一、题目描述

给一个链表数组，每个链表都已按升序排列，把它们合并成一个升序链表。

**示例：**

```
输入: lists = [[1→4→5], [1→3→4], [2→6]]
输出: 1→1→2→3→4→4→5→6

输入: lists = []
输出: null
```

---

## 二、核心思路：合并K个 = 合并两个 + 分治

这题看着吓人，其实只需要会一个基础操作：**合并两个有序链表**（LeetCode 21）。

K 个链表怎么合？分成两半，左半合并、右半合并，再把两个结果合并。就是归并排序的套路。

```
合并 4 个链表：

[list0] [list1] [list2] [list3]
   \     /         \     /
  merge            merge
    |                |
  [合并0,1]      [合并2,3]
     \              /
      \            /
        merge
          |
      [最终结果]

等价于：二叉树从叶到根，每层合并一次
```

为什么好记？因为：

| 你已经会的 | 这题用的 |
|------------|----------|
| 合并两个有序链表 | 就是归并的 merge 操作 |
| 归并排序 | 就是分治 + merge |
| 合并 K 个链表 | = 归并排序对链表数组做一遍 |

**一句话：把 K 个链表当数组，对它们做归并排序。**

## 三、先搞定 mergeTwoLists

这是整个解法的基石，必须秒写。

```go
func mergeTwoLists(a, b *ListNode) *ListNode {
    dummy := &ListNode{}
    tail := dummy

    for a != nil && b != nil {
        if a.Val < b.Val {
            tail.Next = a
            a = a.Next
        } else {
            tail.Next = b
            b = b.Next
        }
        tail = tail.Next
    }

    // 剩下的直接接上
    if a != nil {
        tail.Next = a
    } else {
        tail.Next = b
    }

    return dummy.Next
}
```

记忆要点：

```
dummy + tail 指针
谁小接谁，推进那个指针
一个走完了，另一个整体接上
```

## 四、分治合并 mergeKLists

```go
func mergeKLists(lists []*ListNode) *ListNode {
    if len(lists) == 0 {
        return nil
    }
    return merge(lists, 0, len(lists)-1)
}

func merge(lists []*ListNode, left, right int) *ListNode {
    if left == right {
        return lists[left]       // 只剩一个，直接返回
    }

    mid := left + (right-left)/2
    l := merge(lists, left, mid)    // 合并左半
    r := merge(lists, mid+1, right) // 合并右半

    return mergeTwoLists(l, r)      // 把两半合起来
}
```

就这么短。`merge` 函数就是归并排序的骨架，唯一区别是 merge 操作不是数组赋值，而是调用 `mergeTwoLists`。

## 五、完整流程图解

`lists = [[1→4→5], [1→3→4], [2→6]]`

```
merge(lists, 0, 2)
├── mid = 1
├── l = merge(lists, 0, 1)
│   ├── mid = 0
│   ├── l = merge(lists, 0, 0) → lists[0] = 1→4→5
│   ├── r = merge(lists, 1, 1) → lists[1] = 1→3→4
│   └── mergeTwoLists(1→4→5, 1→3→4)
│       = 1→1→3→4→4→5
├── r = merge(lists, 2, 2) → lists[2] = 2→6
└── mergeTwoLists(1→1→3→4→4→5, 2→6)
    = 1→1→2→3→4→4→5→6

结果: 1→1→2→3→4→4→5→6 ✓
```

展开 `mergeTwoLists(1→4→5, 1→3→4)`：

```
dummy
tail = dummy

1 vs 1 → 接a的1, a后移    dummy→1
4 vs 1 → 接b的1, b后移    dummy→1→1
4 vs 3 → 接b的3, b后移    dummy→1→1→3
4 vs 4 → 接a的4, a后移    dummy→1→1→3→4
5 vs 4 → 接b的4, b后移    dummy→1→1→3→4→4
5 vs nil → b走完，接a      dummy→1→1→3→4→4→5

返回 dummy.Next = 1→1→3→4→4→5
```

## 六、为什么分治比顺序合并好？

顺序合并：先合 list0+list1，结果再合 list2，再合 list3……

```
顺序: ((list0 + list1) + list2) + list3
分治: (list0 + list1) + (list2 + list3)
```

| | 顺序合并 | 分治合并 |
|--|----------|----------|
| 每次合并的长度 | 越来越长 | 尽量等长 |
| 时间复杂度 | O(k²·n) | O(kn·logk) |
| 最坏情况 | 第k次合并长度=k·n | 每层合并总量=kn |

举个例子，4 个链表，每个长度 n：

```
顺序：合并  n + 2n + 3n = 6n（第 k 次，前面已有 k·n 个）
分治：合并  2n + 2n    = 4n（每层总量 kn，共 logk 层）
```

---

## 七、复杂度分析

- **时间**：O(kn·logk)，k 个链表，每个平均 n 个节点，分治 logk 层，每层合并总量 kn
- **空间**：O(logk)，递归栈深度

## 八、容易错的点

### 1. 空数组直接返回 nil

```go
if len(lists) == 0 { return nil }  // 别忘了，否则 lists[0] 越界
```

### 2. merge 递归的终止条件是 left == right

```go
if left == right {
    return lists[left]  // 只剩一个链表，就是结果
}
```

不是 `left > right`，因为 `left > right` 说明区间无效，不应该出现。

### 3. mergeTwoLists 里 dummy 必须有

没有 dummy，第一次接节点时不知道返回谁。`tail` 从 dummy 开始，最后返回 `dummy.Next`。

### 4. 一个走完另一个整体接上

```go
if a != nil {
    tail.Next = a   // 不是遍历逐个接，直接整条接上
} else {
    tail.Next = b
}
```

因为剩余部分本身就是有序的，直接接就完事。

### 5. mid 用 left + (right-left)/2 防溢出

面试中写 `mid := (left + right) / 2` 一般也行，但标准写法是 `left + (right-left)/2`，防止 left+right 溢出。

## 九、面试表达

> 合并 K 个升序链表，用分治法。把 K 个链表从中间分成两半，递归合并左半和右半，然后用合并两个有序链表把结果合起来。合并两个有序链表就是经典的双指针，谁小接谁。分治的好处是每次合并的两个链表长度尽量等长，总时间 O(kn·logk)，比顺序合并的 O(k²·n) 好。空间 O(logk) 是递归栈。
