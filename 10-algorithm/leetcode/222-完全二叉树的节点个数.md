# 222. 完全二叉树的节点个数

题目链接：`https://leetcode.cn/problems/count-complete-tree-nodes/`

---

## 一、题目描述

给定一棵完全二叉树的根节点 `root`，返回这棵树的节点个数。

题目强调：

```text
完全二叉树
```

所以除了普通递归数节点，还可以利用完全二叉树的性质进行优化。

---

## 二、什么是完全二叉树？

完全二叉树满足：

```text
除了最后一层，其它层都是满的；
最后一层节点都尽可能靠左排列。
```

比如这棵是完全二叉树：

```text
        1
      /   \
     2     3
    / \   /
   4   5 6
```

最后一层节点 `4, 5, 6` 都是从左到右连续排列的。

这棵不是完全二叉树：

```text
        1
      /   \
     2     3
      \     \
       5     7
```

因为最后一层不是从左到右依次填充的。

---

## 三、最直观思路：一个一个数

如果暂时想不到完全二叉树优化，直接普通递归也可以。

递归定义：

```text
countNodes(root)：返回以 root 为根的这棵树的节点个数。
```

那么：

```text
当前树节点数 = 左子树节点数 + 右子树节点数 + 当前节点 1
```

代码：

```go
func countNodes(root *TreeNode) int {
    if root == nil {
        return 0
    }

    return countNodes(root.Left) + countNodes(root.Right) + 1
}
```

这个写法对任意二叉树都适用。

---

## 四、普通递归为什么是对的？

对当前节点来说：

```text
如果 root == nil，说明没有节点，返回 0。
如果 root != nil，节点数就是：
左子树节点数 + 右子树节点数 + root 自己。
```

比如：

```text
    1
   / \
  2   3
```

节点数是：

```text
countNodes(2) + countNodes(3) + 1
= 1 + 1 + 1
= 3
```

---

## 五、为什么题目强调完全二叉树？

因为完全二叉树里，经常会出现满二叉树子树。

满二叉树是每一层都填满的二叉树。

例如：

```text
        1
      /   \
     2     3
    / \   / \
   4  5  6  7
```

如果满二叉树高度是 `h`，那么节点数可以直接算：

```text
2^h - 1
```

比如高度为 `3`：

```text
2^3 - 1 = 7
```

这样就不用一个一个递归数了。

---

## 六、怎么判断当前子树是不是满二叉树？

在完全二叉树里，可以比较：

```text
最左路径高度
最右路径高度
```

最左路径高度：

```text
一直往 Left 走
```

最右路径高度：

```text
一直往 Right 走
```

如果：

```text
leftHeight == rightHeight
```

说明这棵子树是满二叉树。

节点数直接是：

```go
(1 << leftHeight) - 1
```

这里要特别注意：

```go
leftHeight := getLeftHeight(root)
rightHeight := getRightHeight(root)
```

传进去的是当前这棵子树的根节点 `root`，不是 `root.Left` 和 `root.Right`。

不要写成：

```go
leftHeight := getLeftHeight(root.Left)
rightHeight := getRightHeight(root.Right)
```

这样会少算当前 `root` 这一层。

我们要判断的是：

```text
以 root 为根的这整棵子树，是不是满二叉树。
```

所以左高应该从 `root` 开始一路往左数：

```text
root -> root.Left -> root.Left.Left -> ...
```

右高也应该从 `root` 开始一路往右数：

```text
root -> root.Right -> root.Right.Right -> ...
```

如果从 `root.Left` 和 `root.Right` 开始数，比较的就变成了：

```text
左子树的最左高度 vs 右子树的最右高度
```

这不是判断当前整棵树是否满的标准。

---

## 七、为什么左右高度相等就是满二叉树？

注意这个判断依赖前提：

```text
当前树是完全二叉树。
```

在完全二叉树中，最后一层节点一定从左到右填充。

如果最左路径高度和最右路径高度一样，说明最后一层最右边也有节点。

既然最后一层最右边都有节点，并且完全二叉树要求从左到右填充，那么最后一层一定填满了。

所以整棵树就是满二叉树。

---

## 八、优化递归思路

对当前 `root`：

```text
1. 如果 root == nil，返回 0
2. 计算最左高度 leftHeight
3. 计算最右高度 rightHeight
4. 如果 leftHeight == rightHeight：
      当前树是满二叉树，直接返回 2^height - 1
5. 否则：
      当前树不是满的，递归计算左右子树节点数
```

伪代码：

```text
countNodes(root):
    if root == nil:
        return 0

    leftHeight = getLeftHeight(root)
    rightHeight = getRightHeight(root)

    if leftHeight == rightHeight:
        return 2^leftHeight - 1

    return countNodes(root.left) + countNodes(root.right) + 1
```

## 九、Go 解法一：普通递归版

```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func countNodes(root *TreeNode) int {
    if root == nil {
        return 0
    }

    return countNodes(root.Left) + countNodes(root.Right) + 1
}
```

这个版本最简单，先掌握它没有问题。

## 十、Go 解法二：完全二叉树优化版

```go
func countNodes(root *TreeNode) int {
    if root == nil {
        return 0
    }

    leftHeight := getLeftHeight(root)
    rightHeight := getRightHeight(root)

    if leftHeight == rightHeight {
        return (1 << leftHeight) - 1
    }

    return countNodes(root.Left) + countNodes(root.Right) + 1
}

func getLeftHeight(root *TreeNode) int {
    height := 0
    for root != nil {
        height++
        root = root.Left
    }
    return height
}

func getRightHeight(root *TreeNode) int {
    height := 0
    for root != nil {
        height++
        root = root.Right
    }
    return height
}
```

核心判断：

```go
if leftHeight == rightHeight {
    return (1 << leftHeight) - 1
}
```

其中：

```text
1 << leftHeight
```

表示：

```text
2^leftHeight
```

所以：

```go
(1 << leftHeight) - 1
```

就是满二叉树节点数。

# Definition for a binary tree node.

## 十二、Python3 解法二：完全二叉树优化版

```python
class Solution:
    def countNodes(self, root: Optional[TreeNode]) -> int:
        if not root:
            return 0

        left_height = self.get_left_height(root)
        right_height = self.get_right_height(root)

        if left_height == right_height:
            return (1 << left_height) - 1

        return self.countNodes(root.left) + self.countNodes(root.right) + 1

    def get_left_height(self, node):
        height = 0
        while node:
            height += 1
            node = node.left
        return height

    def get_right_height(self, node):
        height = 0
        while node:
            height += 1
            node = node.right
        return height
```

## 十三、例子走一遍

树：

```text
        1
      /   \
     2     3
    / \   /
   4   5 6
```

这是完全二叉树，但不是满二叉树。

---

### 根节点 1

最左高度：

```text
1 -> 2 -> 4
height = 3
```

最右高度：

```text
1 -> 3
height = 2
```

左右高度不相等，说明整棵树不是满二叉树。

所以继续递归：

```go
countNodes(root.Left) + countNodes(root.Right) + 1
```

---

### 左子树 2

左子树是：

```text
    2
   / \
  4   5
```

最左高度：

```text
2 -> 4
height = 2
```

最右高度：

```text
2 -> 5
height = 2
```

左右高度相等，说明这棵子树是满二叉树。

直接计算：

```text
2^2 - 1 = 3
```

不用再继续数 `2, 4, 5`。

---

### 右子树 3

右子树是：

```text
  3
 /
6
```

最左高度：

```text
3 -> 6
height = 2
```

最右高度：

```text
3
height = 1
```

左右高度不等，继续递归。

最终节点数是：

```text
6
```

## 十四、普通写法 vs 优化写法

| 写法 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| 普通递归 | 左子树节点数 + 右子树节点数 + 1 | 简单，任何二叉树都能用 | 每个节点都访问，O(n) |
| 完全二叉树优化 | 左右高度相等时直接套满二叉树公式 | 能跳过满子树，复杂度更好 | 需要理解完全二叉树性质 |

面试时可以先写普通版，再补充优化版。

---

## 十五、复杂度分析

### 普通递归

时间复杂度：

```text
O(n)
```

每个节点都访问一次。

空间复杂度：

```text
O(h)
```

递归调用栈高度。

---

### 完全二叉树优化

时间复杂度：

```text
O(log^2 n)
```

原因：

```text
完全二叉树高度是 O(log n)
每一层递归都要计算左右高度，各花 O(log n)
所以整体约为 O(log n * log n)
```

空间复杂度：

```text
O(log n)
```

来自递归调用栈。

---

## 十六、容易错的点

### 1. 普通二叉树不能随便用左右高度相等判断满树

这个优化依赖题目条件：

```text
完全二叉树
```

如果不是完全二叉树，左右高度相等不一定说明是满二叉树。

---

### 2. 高度是节点数，不是边数

这里高度计算是：

```text
经过几个节点，高度就是几。
```

比如单节点树高度是 `1`。

所以满二叉树节点数是：

```text
2^height - 1
```

---

### 3. 位运算公式别写错

正确：

```go
(1 << height) - 1
```

含义是：

```text
2^height - 1
```

---

### 4. 不相等时继续递归左右子树

如果：

```go
leftHeight != rightHeight
```

说明当前树不是满二叉树。

这时不能直接套公式，只能继续递归：

```go
return countNodes(root.Left) + countNodes(root.Right) + 1
```

---

### 5. 计算高度时要从 root 开始，不是从 root.Left/root.Right 开始

正确：

```go
leftHeight := getLeftHeight(root)
rightHeight := getRightHeight(root)
```

错误：

```go
leftHeight := getLeftHeight(root.Left)
rightHeight := getRightHeight(root.Right)
```

原因是我们要判断的是：

```text
当前 root 这整棵树是不是满二叉树。
```

所以左右高度都要包含当前 `root` 这一层。

比如单节点树：

```text
1
```

正确高度应该是：

```text
leftHeight = 1
rightHeight = 1
```

然后节点数：

```text
2^1 - 1 = 1
```

如果从 `root.Left` 和 `root.Right` 开始算，就会得到：

```text
leftHeight = 0
rightHeight = 0
```

然后算出：

```text
2^0 - 1 = 0
```

这就把当前根节点漏掉了。

---

### 6. Go 里函数参数是指针，也不会因为 node = node.Left 改掉外面的 root

高度函数一般写成：

```go
func getLeftHeight(node *TreeNode) int {
    height := 0
    for node != nil {
        height++
        node = node.Left
    }
    return height
}
```

这里 `node` 的类型是指针：

```go
*TreeNode
```

但 Go 的函数参数传递是值传递。

也就是说，调用：

```go
getLeftHeight(root)
```

时，传进去的是 `root` 这个指针值的一份拷贝。

函数内部的 `node` 和外面的 `root` 一开始指向同一个节点，但它们是两个变量。

所以函数里执行：

```go
node = node.Left
```

只是让函数内部的局部变量 `node` 指向了左孩子。

不会改变外面的 `root` 变量。

可以理解成：

```text
指针指向的对象是同一个，
但是指针变量本身是拷贝了一份。
```

所以这种写法是安全的。

但是如果你在函数里改的是节点内容，例如：

```go
node.Val = 100
```

那就会影响外面的树。

因为这不是改 `node` 这个局部变量指向哪里，而是改它指向的那块内存里的内容。

总结：

```text
node = node.Left：只改局部指针变量，不影响外面的 root
node.Val = 100：修改节点内容，会影响外面的树
```

## 十七、面试表达

可以这样说：

> 最直观的做法是普通递归，当前树节点数等于左子树节点数加右子树节点数再加 1，这样时间复杂度是 O(n)。但题目给的是完全二叉树，可以利用完全二叉树性质优化：对于完全二叉树，如果从根一直往左的高度和一直往右的高度相等，说明当前子树是满二叉树，可以直接用公式 `2^height - 1` 得到节点数，不需要继续遍历。否则说明当前子树不是满的，就继续递归计算左右子树。这样可以把时间复杂度优化到 O(log^2 n)。
