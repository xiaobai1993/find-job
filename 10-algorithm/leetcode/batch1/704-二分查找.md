# 704. 二分查找

题目链接：`https://leetcode.cn/problems/binary-search/description/`

---

## 一、题目描述

给定一个升序数组 `nums` 和一个目标值 `target`。

如果 `target` 存在于数组中，返回它的下标。

如果不存在，返回 `-1`。

要求使用：

```text
O(log n)
```

时间复杂度。

所以这题就是标准二分查找。

---

## 二、你的 Go 提交

你的代码：

```go
func search(nums []int, target int) int {
    l,h := 0, len(nums)-1
    for ;l <h ; {
        m := (l +h )/ 2
        v := nums[m]
        if (v > target) {
            h = m-1
        }else if (v < target) {
            l= m+1
        }else {
            return m
        }

    }

    return -1
}
```

主要问题是：

```text
你用了闭区间 [l, h]，但是循环条件写成了 l < h。
```

这会导致最后一个位置没有被检查。

---

## 三、先明确你的区间定义

你的初始化是：

```go
l, h := 0, len(nums)-1
```

这表示搜索区间是：

```text
[l, h]
```

也就是：

```text
左边界包含，右边界也包含。
```

这种叫：

```text
闭区间写法
```

既然右边界 `h` 是 `len(nums)-1`，说明 `h` 这个位置是有效下标，是需要被检查的。

---

## 四、闭区间为什么要用 l <= h？

闭区间 `[l, h]` 里，当：

```text
l == h
```

时，区间里还有一个元素。

这个元素也必须检查。

所以循环条件应该是：

```go
for l <= h {
```

而不是：

```go
for l < h {
```

---

## 五、你的代码为什么会漏掉最后一个元素？

看一个最简单的例子：

```text
nums = [5]
target = 5
```

初始化：

```text
l = 0
h = 0
```

你的循环条件：

```go
l < h
```

判断：

```text
0 < 0 ? false
```

循环根本不进去，直接返回：

```text
-1
```

但正确答案应该是：

```text
0
```

原因就是当 `l == h` 时，你没有检查这个最后剩下的元素。

---

## 六、再看一个容易错的例子

```text
nums = [1, 3]
target = 3
```

初始化：

```text
l = 0
h = 1
```

第一轮：

```text
m = 0
nums[0] = 1
1 < 3
```

所以：

```text
l = m + 1 = 1
```

此时：

```text
l = 1
h = 1
```

目标就在 `nums[1]`。

但你的循环条件是：

```text
l < h
```

也就是：

```text
1 < 1 ? false
```

循环退出，返回 `-1`。

所以闭区间必须用：

```go
l <= h
```

---

## 七、闭区间二分查找模板

先只记这一套，不要同时背两套边界。

```text
搜索区间：[l, h]
初始化：l = 0, h = len(nums)-1
循环条件：l <= h
中点：m = l + (h-l)/2
向右找：l = m + 1
向左找：h = m - 1
```

Go 模板：

```go
func search(nums []int, target int) int {
    l, h := 0, len(nums)-1

    for l <= h {
        m := l + (h-l)/2

        if nums[m] == target {
            return m
        } else if nums[m] < target {
            l = m + 1
        } else {
            h = m - 1
        }
    }

    return -1
}
```

---

## 八、为什么是 h = m - 1 和 l = m + 1？

因为中点 `m` 已经被检查过了。

如果：

```text
nums[m] > target
```

说明 `m` 这个位置太大，目标只可能在左边。

新的搜索区间是：

```text
[l, m-1]
```

所以：

```go
h = m - 1
```

如果：

```text
nums[m] < target
```

说明 `m` 这个位置太小，目标只可能在右边。

新的搜索区间是：

```text
[m+1, h]
```

所以：

```go
l = m + 1
```

---

## 九、为什么中点推荐这样写？

你写的是：

```go
m := (l + h) / 2
```

在 LeetCode 这题里一般也能过。

但更标准的是：

```go
m := l + (h-l)/2
```

原因是避免：

```text
l + h
```

在极大数组情况下整数溢出。

虽然 Go 的 `int` 在普通刷题里通常够用，但面试里写标准写法更稳。

---

## 十、Go 最终推荐写法

```go
func search(nums []int, target int) int {
    l, h := 0, len(nums)-1

    for l <= h {
        m := l + (h-l)/2

        if nums[m] < target {
            l = m + 1
        } else if nums[m] > target {
            h = m - 1
        } else {
            return m
        }
    }

    return -1
}
```

---

## 十一、Python3 写法

```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums) - 1

        while left <= right:
            mid = left + (right - left) // 2

            if nums[mid] < target:
                left = mid + 1
            elif nums[mid] > target:
                right = mid - 1
            else:
                return mid

        return -1
```

## 十三、闭区间和左闭右开不要混用

二分查找最容易错，就是混用了两种区间定义。

---

### 写法一：闭区间 [l, h]

```go
l, h := 0, len(nums)-1

for l <= h {
    m := l + (h-l)/2

    if nums[m] < target {
        l = m + 1
    } else if nums[m] > target {
        h = m - 1
    } else {
        return m
    }
}
```

特点：

```text
h 是有效下标
l == h 时还有一个元素
所以循环条件是 l <= h
```

---

### 写法二：左闭右开 [l, h)

```go
l, h := 0, len(nums)

for l < h {
    m := l + (h-l)/2

    if nums[m] < target {
        l = m + 1
    } else if nums[m] > target {
        h = m
    } else {
        return m
    }
}
```

特点：

```text
h 不是有效下标
l == h 时区间为空
所以循环条件是 l < h
```

---

### 你的问题就是混用了两套

你的初始化：

```go
l, h := 0, len(nums)-1
```

这是闭区间。

但你的循环条件：

```go
l < h
```

更像左闭右开的写法。

所以最后一个元素会被漏掉。

---

## 十四、复杂度分析

时间复杂度：

```text
O(log n)
```

每次搜索区间缩小一半。

空间复杂度：

```text
O(1)
```

只用了几个变量。

---

## 十五、容易错的点

### 1. 闭区间必须用 l <= h

```go
for l <= h {
```

因为 `l == h` 时还有一个元素要检查。

---

### 2. h 初始化成 len(nums)-1

闭区间里，右边界是有效下标：

```go
h := len(nums) - 1
```

---

### 3. 更新边界要跳过 m

因为 `m` 已经检查过了。

```go
l = m + 1
h = m - 1
```

---

### 4. 不要混用区间定义

闭区间就坚持：

```text
[l, h]
l <= h
h = m - 1
```

左闭右开就坚持：

```text
[l, h)
l < h
h = m
```

初学时建议只记闭区间。

---

## 十六、面试表达

可以这样说：

> 这题是标准二分查找。我使用闭区间 `[l, h]`，初始化时 `l = 0`，`h = len(nums)-1`，表示左右边界都是有效下标。因此循环条件要写 `l <= h`，因为当 `l == h` 时区间里还有一个元素需要检查。每次取中点 `m = l + (h-l)/2`，如果 `nums[m]` 小于目标值，说明目标在右侧，令 `l = m + 1`；如果大于目标值，说明目标在左侧，令 `h = m - 1`；如果相等就返回下标。循环结束说明不存在，返回 -1。
