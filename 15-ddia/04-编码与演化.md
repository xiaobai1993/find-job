# Ch4 编码与演化

## 核心思想

系统不可避免地需要变更。编码格式决定了变更的难易程度——**向后兼容**（新代码读旧数据）和**向前兼容**（旧代码读新数据）是演化的关键。

---

## 1. 编码格式对比

| 格式 | 类型 | 人类可读 | 模式 | 向后兼容 | 向前兼容 | 适用场景 |
|------|------|----------|------|----------|----------|----------|
| JSON | 文本 | 是 | 可选 | 难 | 难 | Web API、配置 |
| XML | 文本 | 是 | 可选（XSD） | 难 | 难 | SOAP、企业集成 |
| Protobuf | 二进制 | 否 | 必须 | **好** | **好** | gRPC、内部通信 |
| Thrift | 二进制 | 否 | 必须 | 好 | 好 | 跨语言 RPC |
| Avro | 二进制 | 否 | 必须 | **最好** | **最好** | Kafka、Hadoop |

### JSON 的问题

- **数字精度**：JSON 不区分整数和浮点数，大数溢出
- **二进制数据**：需要 Base64 编码，膨胀 33%
- **模式可选**：没有强制模式 → 兼容性靠约定
- **向前兼容难**：旧代码遇到新字段怎么办？→ 只能忽略未知字段

### Protobuf 的兼容策略

- 每个字段有**编号**（tag），不是名字
- 新字段用新编号 → 旧代码忽略未知编号 → 向前兼容
- 旧字段编号不变 → 新代码仍能读 → 向后兼容
- **不能复用编号**：删除的字段编号必须标记为 reserved

```protobuf
message Payment {
  int64 amount = 1;      // 旧字段，编号不变
  string currency = 2;   // 旧字段
  string reference = 3;  // 新增字段，新编号
  // int64 fee = 4;       // 已删除，reserved
  reserved 4;
}
```

### Avro 的兼容策略

- **读模式**和**写模式**可以不同
- 解码时按读模式解析，忽略写模式中不存在的字段
- 新增字段用**默认值** → 旧代码读新数据时用默认值填充
- Avro 的模式不需要编号 → 更灵活，但需要模式注册表

## 2. 数据流模式

数据需要编码才能在进程间流动。三种主要模式：

### 2.1 通过数据库的数据流

- 写入 → 编码为存储格式
- 读取 → 解码为内存格式
- **关键问题**：新版本代码写入新格式数据 → 旧版本代码读 → 需要向前兼容
- **数据库模式迁移**：比 RPC 模式变更更谨慎，因为数据已经落盘

### 2.2 通过服务的数据流（REST & RPC）

| 维度 | REST | RPC |
|------|------|------|
| 语义 | 资源操作（HTTP 动词） | 方法调用（像本地函数） |
| 兼容 | HTTP 生态成熟 | 需要自己处理兼容 |
| 性能 | 通用 | 可优化（二进制编码） |
| 代表 | OpenAPI/Swagger | gRPC (Protobuf) |

**RPC 的陷阱**：
- 网络请求不像本地调用：可变延迟、部分失败、超时
- **不要假装远程调用是本地调用** → 这是分布式系统最大的谎言

### 2.3 通过消息传递的数据流（异步）

- 消息队列（Kafka/RabbitMQ）作为中间人
- 优势：解耦、缓冲、重试
- 编码：Kafka 用 Avro/Protobuf，需要 Schema Registry

---

## 3. 模式演化的实践

### 向后兼容 vs 向前兼容

| 方向 | 含义 | 重要性 |
|------|------|--------|
| 向后兼容 | 新代码读旧数据 | **必须**（否则旧数据无法处理） |
| 向前兼容 | 旧代码读新数据 | **重要**（滚动升级时旧进程仍在运行） |

### 滚动升级的挑战

- 分布式系统中，不同节点可能运行不同版本
- 升级不是瞬间完成的 → 新旧版本同时存在
- **必须同时满足向后和向前兼容**

### 支付场景关联

- 支付协议变更：新增字段必须向前兼容（旧网关仍能处理）
- Protobuf 是支付系统内部通信的首选（gRPC）
- Kafka 消息用 Avro + Schema Registry → 确保消费者兼容

## 本章面试速查

| 问题 | 答案要点 |
|------|----------|
| 向后兼容 vs 向前兼容？ | 新读旧 vs 旧读新，滚动升级需要两者 |
| Protobuf 怎么保证兼容？ | 字段编号不变，新字段新编号，删除 reserved |
| JSON 的兼容问题？ | 无强制模式，新字段旧代码可能报错 |
| 为什么 RPC 不像本地调用？ | 网络：延迟、部分失败、超时 |
| Avro 为什么兼容最好？ | 读/写模式独立解析，默认值填充 |
