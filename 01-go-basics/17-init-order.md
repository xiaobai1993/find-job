# Go 包初始化顺序与 init() 函数完全解析

---

## 一、先搞懂：Go 程序启动的完整流程

你写的 `main()` 函数不是第一个执行的！在 `main()` 之前，Go runtime 做了一大堆事情：

```
程序启动
  ↓
1. runtime 初始化（调度器、GC、内存分配器...）
  ↓
2. 按依赖顺序初始化所有导入的包
   ├── 包级变量初始化
   └── 执行 init() 函数
  ↓
3. 执行 main 包的包级变量
  ↓
4. 执行 main 包的 init()
  ↓
5. 最后！才执行你的 main() 函数！
```

**面试一句话总结：main() 不是第一个执行的，所有依赖的包都初始化完了才会跑 main()，同一个包内可以有多个 init()。**

---

## 二、同一个包内的初始化顺序

### 1. 包级变量初始化顺序

变量按声明顺序初始化，但有依赖的变量会按依赖顺序排：

```go
var a = 10      // 第一个
var b = a + 5   // 第二个，依赖 a
var c = b + 5   // 第三个，依赖 b

func init() {
    // 第四个，所有变量初始化完了才跑 init
    println(a, b, c)  // 10 15 20
}
```

---

### 2. 同一个文件可以有多个 init() 函数

```go
func init() {
    println("第一个 init")
}

func init() {
    println("第二个 init")  // 同一个文件可以写多个 init！
}

func init() {
    println("第三个 init")
}

// 输出：
// 第一个 init
// 第二个 init
// 第三个 init
```

按声明顺序执行，从上到下。

---

### 3. 同一个包多个文件的 init() 顺序

```
mypackage/
├── a.go   // 里面有 init()
├── b.go   // 里面也有 init()
└── c.go   // 里面也有 init()
```

**按文件名的字典序执行！**
a.go 的 init 先跑，然后 b.go，然后 c.go。

**坑：不要依赖不同文件的 init 执行顺序！** 文件名可能改，顺序就变了。

---

## 三、包之间的初始化顺序：深度优先！

最核心的规则：**按导入路径的深度优先顺序初始化！**

### 例子

```go
// main.go
package main

import (
    "A"
)

func main() {}

// A/A.go
package A

import "B"

// B/B.go
package B

import "C"

// C/C.go
package C
```

依赖关系：main → A → B → C

**初始化顺序：C 先初始化 → B → A → main**

最底层的依赖先初始化，一层一层往上走。

---

### 同一个包只会初始化一次！

```go
// main 导入了 A 和 B
// A 导入了 C
// B 也导入了 C

// 依赖图：
// main → A → C
//      → B → C

// 初始化顺序：C → A → B → main
```

C 虽然被两个包导入，但是只会初始化一次！init() 只会跑一次。

和 sync.Once 一样的效果，Go runtime 自动保证。

## 四、经典面试题：判断输出顺序

这题面试 10 个有 9 个答错！

### 题目

```go
// main.go
package main

import "fmt"

var n = c()

func init() {
    fmt.Println("main init")
}

func c() int {
    fmt.Println("main var c()")
    return 1
}

func main() {
    fmt.Println("main()")
}
```

**请问输出顺序是什么？**

---

### 答案

```
main var c()
main init
main()
```

**顺序：包级变量初始化 → init() 函数 → main()**

永远记住这个顺序！

## 五、循环导入（Cyclic Import）

### 1. 什么是循环导入？

```go
// A 导入 B
package A
import "B"

// B 导入 A
package B
import "A"
```

A 依赖 B，B 依赖 A，死循环了！

**Go 编译器直接报错：import cycle not allowed**

Go 不允许循环导入，从根上就禁止了，编译都过不了。

---

### 2. 怎么解循环导入？

最常见的场景：A 和 B 互相调用对方的函数。

**解法 1：拆出公共的 C 包**
把 A 和 B 都需要的函数、类型、接口拆到第三个包 C，A 和 B 都导入 C。

**解法 2：用接口解耦**
不要直接导包调用，把对方的接口定义在自己包里，传进来的时候用接口。

```go
// 不要直接 import B 然后调 B.Foo()
// 而是定义接口：
type BFoo interface {
    Foo()
}

// 调用的时候传进来
func MyFunc(b BFoo) {
    b.Foo()
}
```

**解法 3：回调函数**
不要直接调用，把对方的函数当参数传进来。

## 六、init() 的常见用法与坑

### 1. init() 的常见用法

| 场景 | 例子 |
|------|------|
| 初始化全局变量 | 初始化配置、数据库连接池 |
| 注册 | 注册 driver、注册路由、注册插件 |
| 计算 | 预计算一些常量、查表 |
| 做 side effect | 匿名导入包只执行它的 init |

**最经典的：导入 mysql driver**
```go
import (
    "database/sql"
    _ "github.com/go-sql-driver/mysql"  // 匿名导入，只跑它的 init() 注册 driver
)
```

---

### 2. 坑 1：init() 里 panic，很难调试

```go
func init() {
    // 这里 panic 了，堆栈信息很难看
    // 而且是 main 之前跑的，你自己的代码还没开始
    panic("init failed")
}
```

**最佳实践：init() 尽量只做简单的初始化，复杂逻辑放 main() 里！**

---

### 3. 坑 2：init() 执行顺序不可靠

不要依赖不同包的 init 执行顺序！

除了"被导入的包先于导入它的包初始化"，其他顺序 Go 不做任何保证！

不同编译器版本、不同平台、不同构建方式顺序可能都不一样。

---

### 4. 坑 3：测试的时候也会跑 init()

你写测试的时候，所有导入的包的 init() 都会跑一遍！

包括你测试的包，以及它所有依赖的包。

**所以 init() 里不要搞什么全局副作用，不然测试会互相影响！**

---

### 5. 坑 4：init() 不能显式调用

```go
func main() {
    init()  // ❌ 编译错误！init 只能 runtime 自动调用
}
```

init() 是特殊函数，你自己不能调。

---

## 七、最佳实践总结

1. ✅ **init() 尽量简单**，复杂初始化逻辑放 main 里
2. ✅ **不要依赖 init() 的执行顺序**，除了深度优先的基本保证
3. ✅ **循环导入了就拆公共包**，不要试图 hack
4. ✅ **匿名导入只用来做注册 side effect**，比如 driver
5. ❌ **不要在 init() 里做 IO**，失败了很难处理
6. ❌ **不要在 init() 里启动 goroutine**，main 还没跑 goroutine 就跑了，很难管理
7. ❌ **不要依赖不同文件的 init 顺序**，文件名可能改

---

## 八、面试高频问答

| 问题 | 答案 |
|------|------|
| main() 是第一个执行的吗？ | 不是。所有依赖包的变量初始化和 init() 跑完，然后 main 包的变量和 init()，最后才跑 main()。 |
| 同一个包内初始化顺序？ | 先包级变量按顺序初始化，然后按声明顺序执行所有 init() 函数。 |
| 包之间的初始化顺序？ | 深度优先，被依赖的包先初始化。 |
| 同一个包会被初始化几次？ | 只会一次，不管被多少个包导入。 |
| 同一个文件可以有多个 init() 吗？ | 可以，按声明顺序从上到下执行。 |
| 同一个包多个文件的 init() 执行顺序？ | 按文件名字典序。但不要依赖这个，文件名可能改。 |
| 什么是循环导入？ | A 导 B，B 导 A，形成循环，Go 直接编译报错。 |
| 怎么解循环导入？ | 拆公共包、用接口解耦、传回调函数。 |
| init() 可以自己调用吗？ | 不行，只能 runtime 自动调用，显式调用编译错误。 |
| 为什么要匿名导入包？ | 只想执行那个包的 init()，不想用里面的任何东西，最常见的是注册 database driver。 |
| 测试的时候 init() 会跑吗？ | 会，所有导入的包的 init() 都会跑，所以 init() 不要有全局副作用。 |
| 包级变量和 init() 谁先执行？ | 包级变量先初始化，所有变量初始化完了才执行 init()。 |

---

## 九、一句话总结

> Go 初始化顺序是深度优先，包变量先初始化然后 init()，所有依赖包初始化完了才跑 main()；同一个包可以有多个 init()，循环导入编译不通过，init() 尽量简单不要搞复杂逻辑。
