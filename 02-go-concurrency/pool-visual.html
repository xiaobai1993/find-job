关键说明

本地池 + 窃取
Private：当前 P 专属，Get/Put 完全无锁，性能最高
Shared：共享链表，本 P 从头部拿，其他 P 从尾部窃取（需加锁）
Get 查找顺序：private → shared 头部 → 其他 P shared 尾部 → victim → New()
99% 命中 private，跨 P 窃取概率极低
两轮 GC 清理机制
第 1 次 GC：local → victim，清空 local，旧 victim 被丢弃
第 2 次 GC：victim 被清空，对象真正释放
效果：对象至少活过一轮 GC，最多两轮 GC
Victim 缓存是 Go 1.15 引入的重要优化，避免 GC 后瞬间大量分配
正确用法
✅ bytes.Buffer、JSON 序列化缓冲区、临时结构体
✅ 对象 > 1KB 或分配开销大的才值得用 Pool
✅ Get 出来后必须 Reset，否则携带旧数据
✅ Put 回去前也要确保对象状态干净
常见坑
❌ 存数据库连接/TCP 连接 → GC 清 Pool 不调 Close()，连接泄漏
❌ Get 后忘记 Reset → 上次金额、订单号带到下次请求，资金故障
❌ 存大对象 → 高并发下池里对象越来越多，内存飙升
❌ 太小的对象用 Pool → Pool 开销比对象分配还大
