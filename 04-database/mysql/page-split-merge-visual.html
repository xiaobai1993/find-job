页分裂 ① — 顺序插入（AUTO_INCREMENT 主键）
页分裂 ② — 随机插入（UUID / 无序主键）
页合并 — 删除记录触发合并（MERGE_THRESHOLD = 50%）
自增主键 vs UUID 主键 — 页分裂对比
AUTO_INCREMENT（顺序）UUID / 随机主键
插入位置始终追加到末尾随机位置，可能落在页中间
分裂触发频率极低，页填满才开新页高，每次随机插入都可能触发
分裂后页利用率旧页 ~100%，新页从头积累两页各 ~50%，空间浪费翻倍
索引碎片几乎没有严重，B+ 树高度增加
写入性能高，顺序 IO低，随机 IO + 频繁分裂
Buffer Pool 效率高，页紧凑命中率高低，碎片多占用更多缓存槽
MERGE_THRESHOLD 可以在建表时调整，默认 50%。
CREATE TABLE t (...) COMMENT='MERGE_THRESHOLD=40';
调低阈值 → 减少合并频率，但页平均利用率会下降。

碎片治理：OPTIMIZE TABLE orders; 重建整张表消除页碎片（大表用 pt-online-schema-change 避免锁表）。
一句话记忆
页分裂页满了装不下 → 一分为二。顺序插入：旧页满、新页空，代价小；随机插入：各拿一半，空间浪费，碎片重
页合并删太多页太空（低于 50%）→ 相邻两页合一，释放空页，父节点更新
自增主键始终顺序插入 → 几乎不分裂 → 紧凑高效 → 推荐默认选择
UUID 主键随机插入 → 频繁分裂 → 大量半空页 → 写多场景避免使用
