MySQL 联合索引 B+ 树结构

以联合索引 (name, age) 为例，与单列索引对比

示例数据表
CREATE TABLE users (
  id INT PRIMARY KEY,
  name VARCHAR(20),
  age INT,
  city VARCHAR(20),
  INDEX idx_name (name), -- 单列索引
  INDEX idx_name_age (name, age) -- 联合索引
);
-- 示例数据（id / name / age / city）
(1, '李明', 22, '北京')  (2, '李明', 28, '上海')  (3, '王芳', 19, '广州')

name 不同时先比 name；name 相同时比 age
排序规则 先按 name 字典序排，name 相同时再按 age 升序排
叶子存储 (name, age, 主键id) — city 不在索引里，查 city 仍需回表
覆盖索引 SELECT name, age FROM users WHERE name='李明' 不需要回表（索引即结果）
最左前缀 只有从 name 开始查，才能命中索引；跳过 name 单独查 age 无法走索引
最左前缀规则 — 哪些查询能走联合索引？
查询条件 能否走 idx_name_age(name, age) 原因
WHERE name = '李明' ✓ 走索引（name 部分） 命中最左列，可定位到 name='李明' 的叶子区间
WHERE name = '李明' AND age = 22 ✓ 走索引（name + age） 两列都命中，精确定位到单条叶子记录
WHERE name = '李明' AND age > 20 ✓ 走索引（name 精确 + age 范围） name 等值 + age 范围扫描，ICP 可过滤
WHERE name LIKE '李%' ✓ 走索引（name 前缀） 前缀模糊匹配，仍可用 name 做范围扫描
WHERE age = 22 ✗ 不走索引 跳过了最左列 name，B+树无法定位起始位置
WHERE name LIKE '%明' ✗ 不走索引 左侧通配符，无法用 B+ 树二分查找
WHERE name = '李明' AND age != 22 △ name 部分走索引 name 能命中，age 的不等值条件退化为全扫
单列索引 vs 联合索引 — 核心差异
单列索引 idx_name(name) 联合索引 idx_name_age(name, age)
叶子节点存什么 (name, id) (name, age, id)
排序方式 仅按 name 排序 先按 name，再按 age（字典序嵌套）
SELECT name, age 是否回表 需要回表（age 不在索引里） 不需要（覆盖索引）
索引条件下推 (ICP) 只能对 name 过滤 可在回表前同时过滤 name 和 age
索引大小 小（只存 name） 略大（存 name + age）
核心记忆：联合索引的 B+ 树和单列索引 结构完全一样， 区别只在于 叶子节点的 key 变成了多列的组合， 并且排序是 按列顺序逐级比较（先比第一列，相同再比第二列……）。 这就是最左前缀规则的根本原因——B+ 树是按第一列排好序的， 跳过第一列就无法二分定位。
