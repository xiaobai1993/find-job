# 进程、线程、协程 — 后端面试核心考点

来源：操作系统教材 + 面试高频题整理

---

## 一、进程 vs 线程 vs 协程

这是面试开场高频题，核心是理解**调度主体**和**资源隔离程度**的区别。

| 特性 | 进程 | 线程 | 协程（Goroutine） |
|------|------|------|-------------------|
| 调度方 | 操作系统内核 | 操作系统内核 | 用户态（Go runtime） |
| 切换开销 | 大（需切换页表、TLB、寄存器） | 中（共享地址空间，只切换寄存器/栈） | 小（只切换几个寄存器，栈很小） |
| 地址空间 | 独立，互不影响 | 共享进程地址空间 | 共享进程地址空间 |
| 通信方式 | IPC（管道、共享内存、信号等） | 共享内存（但要加锁） | 共享内存 + channel |
| 创建开销 | 大（fork 需复制页表等） | 中（clone 共享地址空间） | 极小（2KB 栈起步） |
| 崩溃影响 | 只影响自己 | 一个线程崩→整个进程崩 | goroutine panic 可 recover |
| 数量上限 | 几百~几千 | 几千~几万 | 百万级 |

**面试答法**：不要背表，从「为什么要有线程」开始讲——

> 进程隔离性好但太重，线程共享地址空间轻量但内核调度开销仍然不小。协程把调度搬到用户态，切换只保存几个寄存器，Go 的 goroutine 初始栈只有 2KB 动态增长，所以能轻松开百万个。

## 二、进程间通信（IPC）

面试常问：「进程间有哪些通信方式？各自优缺点？」

| 方式 | 原理 | 优缺点 | 典型场景 |
|------|------|--------|----------|
| 管道（pipe） | 半双工，父子进程间传递字节流 | 简单但只能单向、必须父子关系 | shell 命令管道 `ps aux | grep nginx` |
| 命名管道（FIFO） | 文件系统中的特殊文件，任意进程可打开 | 比普通 pipe 灵活，但还是字节流 | 两个独立进程通信 |
| 消息队列 | 内核维护的消息链表，按类型读取 | 有格式、可按类型筛选，但拷贝开销 | 进程间传递结构化消息 |
| 共享内存 | mmap 映射同一块物理内存到各自地址空间 | 最快（零拷贝），但需要自行同步 | 高性能数据共享（如 Kafka 的消息存储） |
| 信号量 | 内核计数器，用于控制共享资源访问 | 只做同步，不做数据传递 | 配合共享内存做互斥 |
| 信号 | 内核向进程发送异步通知（SIGKILL、SIGTERM 等） | 只能通知事件，不能传数据 | kill 进程、通知子进程退出 |
| Socket | 网络通信接口，也可用于本地（Unix socket） | 最通用，支持跨机器 | 微服务间 RPC 通信 |

**面试加分点**：

- 共享内存最快因为**零拷贝**——数据不需要从内核态拷贝到用户态
- 但共享内存必须配合信号量或其他同步机制，否则有竞态
- Go 里的 `os/signal` 包处理信号，channel 本质上是用户态的消息队列

## 三、进程状态与生命周期

经典五状态模型（面试经常画状态转换图）：

```
创建 → 就绪 → 运行 → 阻塞 → 就绪
                ↓
              终止
```

| 状态 | 含义 |
|------|------|
| 创建（New） | 分配资源、初始化 PCB |
| 就绪（Ready） | 已具备运行条件，等 CPU 调度 |
| 运行（Running） | 正在 CPU 上执行 |
| 阻塞（Blocked/Waiting） | 等待 I/O 或事件，主动放弃 CPU |
| 终止（Terminated） | 执行完毕或被 kill |

**关键区分**：

- **就绪→运行**：被调度器选中（抢占式或时间片轮转）
- **运行→阻塞**：进程主动请求 I/O 或 sleep，**不是被抢占**
- **运行→就绪**：时间片用完或被更高优先级抢占

面试陷阱：「阻塞是进程被强制暂停吗？」→ **不是，阻塞是进程主动发起的等待行为**。

## 四、调度算法

| 算法 | 特点 | 适用场景 |
|------|------|----------|
| FCFS（先来先服务） | 简单公平，短进程可能等很久 | 不追求响应时间的批处理 |
| SJF（短作业优先） | 平均等待时间最小，但长作业可能饿死 | 理论最优，实际难预估作业长度 |
| RR（时间片轮转） | 每个进程分配固定时间片，轮流执行 | 交互式系统，保证响应时间 |
| 优先级调度 | 按优先级选进程，可抢占或非抢占 | 实时系统 |
| CFS（完全公平调度器） | Linux 默认调度算法，虚拟运行时间排序 | Linux 通用场景 |

**Linux CFS 要点**：

- 每个进程维护 `vruntime`（虚拟运行时间）
- 实际运行时间按权重折算成 vruntime：`vruntime += 实际运行时间 × (NICE_0_LOAD / 进程权重)`
- 选 vruntime 最小的进程运行→自然公平
- Go runtime 的 GMP 模型是另一套逻辑，不走 CFS

## 五、上下文切换开销

面试常问：「线程切换比进程切换快多少？为什么？」

**进程切换需要保存/恢复**：
1. 通用寄存器（~16 个）
2. 程序计数器（PC）、栈指针（SP）
3. **页表基址寄存器**（CR3）→ TLB 全刷！
4. 浮点寄存器、 SIMD 寄存器
5. 内核栈

**线程切换省掉了什么**：
- 不需要切换页表（共享地址空间）
- 不需要刷 TLB（Translation Lookaside Buffer）
- TLB 刷新是进程切换最大的开销来源

**协程切换省掉了什么**：
- 上面全部在用户态完成，不需要陷入内核
- Go runtime 只保存 SP、PC、DX 等 ~14 个寄存器
- 栈切换只是改 SP 指针，因为 goroutine 栈是连续分配的

**面试答法**：进程切换≈几微秒，线程切换≈1微秒，协程切换≈几十纳秒。核心差距来自 TLB 刷新和内核态切换。

## 六、死锁

四个必要条件（背下来 + 能解释）：

1. **互斥**：资源只能被一个进程占用
2. **持有并等待**：拿着已有资源，又等新资源
3. **不可抢占**：已获得的资源不能被强制收回
4. **循环等待**：A 等 B，B 等 C，C 等 A

**破坏策略**（面试追问「怎么避免死锁」）：

| 条件 | 破坏方法 |
|------|----------|
| 互斥 | 有些资源可以设计为共享（如只读文件），但大多数互斥很难破坏 |
| 持有并等待 | 一次性申请所有资源（Go 里可以用 `sync.Mutex` + 顺序锁） |
| 不可抢占 | 设置超时自动释放（Go 的 `context.WithTimeout`） |
| 循环等待 | 对资源编号，按序申请（最实用） |

**Go 面试角度**：

- `sync.Mutex` 本身不会死锁，但多个锁交叉使用会
- 解决方式：统一加锁顺序 + context 超时控制
- channel 也可能死锁：双方都阻塞在收/发且没有 buffer

## 七、僵尸进程与孤儿进程

| 概念 | 含义 | 危害 | 处理 |
|------|------|------|------|
| 僵尸进程 | 子进程已终止但父进程未调用 `wait()`，PCB 仍留在内核 | 占用 PID 和内核资源，PID 耗尽则无法创建新进程 | 父进程 `wait()/waitpid()`；杀父进程让 init 接管 |
| 孤儿进程 | 父进程先终止，子进程被 init（PID 1）接管 | 无危害，init 会自动回收 | 不需要处理 |

**面试答法**：僵尸进程的危害不是「占用大量内存」，而是**占用 PID 号**——Linux PID 上限通常 32768，僵尸进程太多会耗尽 PID 导致无法 fork。

Go 里 `os/exec` 创建子进程后会自动 `Wait()`，不会产生僵尸进程。

## 八、Go runtime 的 GMP 模型（进程线程知识的延伸）

这是 Go 后端面试必考题，本质是对操作系统调度模型的用户态重实现。

| 概念 | 含义 |
|------|------|
| G（Goroutine） | 用户态轻量线程，初始栈 2KB |
| M（Machine/Thread） | 操作系统线程，由内核调度 |
| P（Processor） | 逻辑处理器，持有本地 G 队列（256 个），GOMAXPROCS 控制 P 数量 |

**调度流程**：
1. P 的本地队列里有 G → M 绑定 P 执行 G
2. 本地队列空 → 从全局队列取一批 G
3. 全局队列也空 → 从其他 P 偷一半（work stealing）
4. G 遇到 syscall 阻塞 → M 与 P 解绑，P 找新 M 继续跑其他 G
5. syscall 返回 → M 尢尬，先尝试抢回原来的 P，不行就找空闲 P，还不行就把 G 放全局队列自己休眠

**面试追问**：「为什么需要 P？G 直接挂 M 不行吗？」

> 没有 P 的话，每个 M 都要从全局队列抢 G→全局锁竞争激烈。P 的本地队列让大部分 G 调度不需要加锁。work stealing 让负载自然均衡。
