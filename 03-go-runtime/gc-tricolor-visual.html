三种写屏障对比

点击每种写屏障卡片展开详细规则。混合写屏障是 Go 1.8+ 的核心创新，不需要重新扫描栈。

插入写屏障（Go 1.5 ~ 1.7）

  • 规则插入新引用时，把新引用的对象涂灰
  • 问题栈上不开写屏障（性能太差）
  • STW标记结束后必须重新扫描所有栈
  • 典型STW10 ~ 50 ms

删除写屏障

  • 规则删除引用时，把被删引用的对象涂灰
  • 问题保守，多标记很多对象
  • 缺点产生大量"浮动垃圾"
  • 效果内存占用升高，但不会漏标

混合写屏障（Go 1.8+，革命性！）

  • 规则1GC 开始时，把所有 goroutine 的栈全部扫描涂黑
  • 规则2之后栈上新建的对象，全部是黑色
  • 规则3插入新引用时，把新引用的对象涂灰
  • 规则4删除旧引用时，把旧引用的对象涂灰
  • 核心不需要重新扫描栈！STW 从 10ms+ 降到几百 us
面试必背：栈变黑，插入涂灰，删除也涂灰！最大的好处是不需要重新扫描栈了。

GC 完整四阶段流程（Go 1.8+）

点击每个阶段展开详细说明。总 STW 仅 0.1 ~ 0.6 ms！

1
STW 1：开启写屏障，扫描栈涂黑
停止所有 G → 开启混合写屏障 → 扫描所有栈涂黑 → 根对象涂灰入队
STW 10~100us
1. 停止所有 goroutine
2. 开启混合写屏障
3. 扫描所有 goroutine 的栈，把栈上所有对象全部涂黑（这是混合写屏障的核心！）
4. 把根对象（全局变量等）全部涂成灰色，放入灰色队列
5. STW 很短，因为只是扫栈，几微秒到几百微秒
↓
2
并发标记
GC worker 从灰色队列取对象 → 涂黑 → 引用涂灰 → 直到灰色队列为空
无 STW
1. 专门的 GC worker goroutine 从灰色队列拿对象
2. 把对象涂黑，把它引用的对象涂灰
3. 一直循环，直到灰色队列为空
4. 和用户代码并行跑，完全不影响！
5. 这是 Go GC 最牛逼的地方：标记阶段 99% 的时间都是并发的
↓
3
STW 2：关闭写屏障，收尾
停止所有 G → 关闭写屏障 → 清理工作 → 处理剩余根对象
STW 100~500us
1. 停止所有 goroutine
2. 关闭写屏障
3. 做一些清理工作
4. 处理剩下的根对象
5. 这就是 Go GC 主要的 STW，一般几百微秒，几乎感知不到
↓
4
并发清除
遍历堆 → 白色对象回收 → 放入空闲列表
无 STW
1. 遍历整个堆
2. 把白色对象回收，放到 mcache 的空闲列表
3. 后台慢慢清，用户代码完全不感知
4. 和用户代码并行跑
总 STW = 0.1 ~ 0.6 ms！两次 STW 都极短，几乎感知不到。Go 1.8+ 混合写屏障不需要重新扫描栈，是 STW 大幅降低的核心原因。

GC 演进历史

点击每个版本展开详细说明。Go GC 从几秒 STW 演进到几百微秒。

Go 1.0（2012）— 串行标记清除
STW: 几百ms ~ 几秒 | 单线程 GC，所有 G 都停
标记和清除都是单线程的，整个程序完全停止。堆越大，STW 越长，几秒的停顿很常见。这是 Go 最早的 GC，性能很差。
Go 1.3（2014）— 并行标记清除
STW: 几十 ~ 几百 ms | 标记并行，清除并行
标记和清除都变成了多线程并行，但还是需要 STW。比 Go 1.0 快了很多，但几十到几百毫秒的停顿仍然不可接受。
Go 1.5（2015）— 三色标记 + 插入写屏障
STW: 10 ~ 50 ms | 并发标记！革命性改进！
引入三色标记和插入写屏障，实现了真正的并发标记！标记阶段用户代码可以继续跑。但栈上不开写屏障，标记结束后需要 STW 重新扫描所有栈，STW 仍然有 10~50ms。
Go 1.8（2017）— 混合写屏障
STW: 0.5 ~ 2 ms | 不需要重扫栈！STW 降低 10 倍！
GC 最大的里程碑！混合写屏障 = 插入写屏障 + 删除写屏障 + 栈一开始就涂黑。不需要重新扫描栈了！STW 从几十毫秒降到几百微秒，降低了 10~50 倍。这是 Go GC 最牛逼的一次升级。
Go 1.19（2022）— GOMEMLIMIT + 清扫优化
STW: 0.1 ~ 1 ms | 容器环境神器！
1. GOMEMLIMIT 软内存限制：超过限制后 GC 频率自动升高，避免容器 OOM
2. GC 清扫 CPU 限流：最多用 50% CPU，避免清扫打满 CPU
3. 大页支持：标记速度提升 10~20%
面试加分项：Go 1.8 是 GC 最大的一次提升，STW 降了 10 倍！核心是混合写屏障不需要重新扫描栈。Go 1.19 的 GOMEMLIMIT 是容器环境救星！
